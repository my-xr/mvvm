1.1 单项选择题（30 题）

01-选择-001（★ 知识点：K1-1 前端演进） 前端开发演进的正确顺序是？

  • A jQuery → 原生 JS → MVVM 框架
  • B 原生 JS → MVVM 框架 → jQuery
  • C 原生 JS → jQuery → MVVM 框架
  • D MVVM 框架 → jQuery → 原生 JS

答案：C 解析：前端演进顺序为”原生 JS → jQuery（封装 DOM）→ MVVM 框架（数据驱动）“。驱动演进的根本动力是前端复杂度上升。C 正确。

01-选择-002（★ 知识点：K1-1 前端演进） 驱动前端从”原生 JS 操作 DOM”演进到”使用框架”的根本动力是？

  • A 浏览器版本升级
  • B 前端应用复杂度不断上升
  • C JavaScript 语法更新
  • D HTML 标准变化

答案：B 解析：随页面交互复杂度上升，直接操作 DOM 越发力不从心，才催生了封装（jQuery）和框架（MVVM）。根本动力是复杂度上升，B 正确。

01-选择-003（★ 知识点：K1-1 前端演进） 下列关于 jQuery 的说法，正确的是？

  • A jQuery 是一个 MVVM 框架
  • B jQuery 实现了数据双向绑定
  • C jQuery 封装了 DOM 操作，但本质仍是命令式
  • D jQuery 已经完全被淘汰，无人使用

答案：C 解析：jQuery 只是封装了 DOM 操作，仍是命令式，没有数据驱动与双向绑定，不是 MVVM 框架。它也未被完全淘汰，简单页面仍适用。C 正确。

01-选择-004（★ 知识点：K1-2 MVVM） MVVM 中，“M” 代表的是？

  • A Manager
  • B Model
  • C Module
  • D Method

答案：B 解析：MVVM = Model-View-ViewModel，M 代表 Model（模型/数据）。B 正确。

01-选择-005（★ 知识点：K1-2 MVVM） 在 MVVM 架构中，连接 Model 与 View 的桥梁是？

  • A Controller
  • B Router
  • C ViewModel
  • D Service

答案：C 解析：MVVM 中 ViewModel 是 Model 与 View 之间的桥梁，负责数据绑定、事件处理与自动同步。Controller 是 MVC 的概念。C 正确。

01-选择-006（★ 知识点：K1-2 MVVM） 在 MVVM 中，ViewModel 最核心的作用是？

  • A 强制所有数据只能单向流动
  • B 在数据和视图之间建立绑定关系，并处理交互同步
  • C 提供依赖注入容器
  • D 实现控制反转

答案：B 解析：ViewModel 负责连接 Model 与 View。数据变化时驱动视图更新；用户输入或触发事件时，再由 ViewModel 更新数据。Vue 中表单双向绑定通常通过 v-model 实现，但并不表示所有数据都必须双向同步。B 正确。

01-选择-007（★ 知识点：K1-2 MVVM） 在 MVVM 中，开发者的主要工作变为？

  • A 手动操作 DOM 更新视图
  • B 操作 Model（数据），由框架自动更新视图
  • C 编写 SQL 语句
  • D 配置服务器

答案：B 解析：MVVM 让开发者聚焦于数据（Model），视图由框架自动维护，无需手动操作 DOM。这是与原生 JS 的本质区别。B 正确。

01-选择-008（★ 知识点：K1-2 MVVM） 在 Vue 中，承担 ViewModel 角色的是？

  • A HTML 文件
  • B Vue 实例/组件本身
  • C 浏览器
  • D Node.js

答案：B 解析：在 Vue 中，Vue 实例/组件本身就是 ViewModel，负责把数据与视图绑定起来。<script setup> 里的响应式数据是 Model，<template> 是 View。B 正确。

01-选择-009（★ 知识点：K1-3 Vue3） Vue 框架的创建者是？

  • A Jordan Walke
  • B 尤雨溪（Evan You）
  • C Misko Hevery
  • D Dan Abramov

答案：B 解析：Vue 由华人尤雨溪（Evan You）于 2014 年创建。Jordan Walke 创建了 React；Misko Hevery 创建了 Angular；Dan Abramov 是 Redux/React 核心贡献者。B 正确。

01-选择-010（★ 知识点：K1-3 Vue3） Vue 3 推荐使用的 API 风格是？

  • A Options API
  • B Composition API
  • C Class API
  • D Hooks API

01-选择-011（★ 知识点：K1-3 Vue3） Vue 3 用于实现响应式的底层技术是？

  • A Object.defineProperty
  • B Proxy
  • C Reflect.set
  • D MutationObserver

答案：B 解析：Vue 3 用 ES6 Proxy 替代 Vue 2 的 Object.defineProperty 实现响应式，能监测属性增删，性能更好。B 正确。

01-选择-012（★ 知识点：K1-3 Vue3） 下列哪一项不是 Vue 3 相比 Vue 2 的改进？

  • A 引入 Composition API
  • B 用 Proxy 实现响应式
  • C 包体积更小、性能提升
  • D 移除了对单文件组件的支持

答案：D 解析：Vue 3 仍支持单文件组件（SFC），并未移除。A、B、C 都是 Vue 3 的真实改进。D 错误，故选 D。

01-选择-013（★ 知识点：K1-4 Node.js） 关于 Node.js，下列说法正确的是？

01-选择-023（★★ 知识点：K1-1/K1-2） 下列关于”原生 JS 操作 DOM”与”MVVM 数据驱动”的区别，说法正确的是？

答案：B 解析：原生 JS 是命令式，手动操作 DOM；MVVM 是声明式，开发者管数据，框架自动更新视图。B 正确。

01-选择-024（★★ 知识点：K1-2 MVVM） 关于 MVVM 中“数据绑定”和“表单双向绑定”，下列说法正确的是？

  • A MVVM 表示所有数据都必须双向同步
  • B 数据变化可以驱动视图更新；用户输入通常经事件或 v-model 由 ViewModel 回写数据
  • C View 可以直接修改 Model，绕过 ViewModel
  • D 双向绑定需要开发者手动查询 DOM 并同步数据

答案：B 解析：MVVM 更准确地说是通过数据绑定和响应式机制连接 Model 与 View。普通展示多是“数据→视图”，表单输入可通过 v-model 或事件处理形成“视图→数据”的回写。B 正确。

答案：B 解析：Vue 3 推荐 Composition API，但仍支持 Options API，二者可共存。性能与 API 风格无关，Composition API 优势在逻辑组织与复用。B 正确。

01-选择-028（★★ 知识点：K1-4 npm） 关于 node_modules 目录，下列说法正确的是？

01-选择-029（★★ 知识点：K1-5 Vite） 关于 Vite 启动速度快的原因，下列说法正确的是？

  • A Vite 启动时把所有模块打包后再启动
  • B Vite 利用浏览器原生 ESM，按需编译，启动几乎不打包

01-选择-040（★★ 知识点：K1-1/K1-2/K1-3 综合） 下列说法正确的有？（多选）

参考答案： （1）痛点与 MVVM 解决（6 分）： - 原生 JS 痛点（3 分）：需手动操作 DOM（清空列表、逐个创建 li）、数据与视图耦合、搜索过滤时要手动重渲染、状态一多易混乱难维护。 - MVVM 解决（3 分）：数据驱动视图，只需维护任务数据数组与搜索关键词，用 v-for 渲染列表、computed 计算过滤结果，数据变化视图自动更新，无需手动操作 DOM。 （2）MVVM 三角色对应（每点 2 分，共 6 分）： - Model：任务数据数组（如 tasks = [{id, title, status}]）和搜索关键词 keyword； - View：<template> 中的界面（输入框 + 任务列表 ul/li）； - ViewModel：Vue 组件本身（<script setup> 中的响应式数据与计算属性），负责把数据绑定到视图。 （3）完整代码（8 分）：

<script setup>
import { ref, computed } from 'vue'

// Model：任务数据与搜索关键词
const keyword = ref('')
const tasks = ref([
  { id: 1, title: '任务一：搭建项目', status: '进行中' },
  { id: 2, title: '任务二：实现登录', status: '未开始' },
  { id: 3, title: '任务三：接口联调', status: '未开始' }
])

// ViewModel：计算过滤后的任务
const filteredTasks = computed(() =>
  tasks.value.filter(t => t.title.includes(keyword.value))
)
</script>

<template>
  <div class="ctts-tasks">
    <h1>CTTS-Frontend 任务列表</h1>
    <input v-model="keyword" placeholder="搜索任务" />
    <ul>
      <li v-for="t in filteredTasks" :key="t.id">
        {{ t.title }} — {{ t.status }}
      </li>
    </ul>
    <p v-if="filteredTasks.length === 0">暂无匹配任务</p>
  </div>
</template>

<style scoped>
.ctts-tasks {
  max-width: 600px;
  margin: 40px auto;
  font-family: system-ui, sans-serif;
}
input {
  padding: 8px;
  width: 100%;
  box-sizing: border-box;
  margin-bottom: 16px;
}
li {
  padding: 8px 0;
  border-bottom: 1px solid #eee;
  list-style: none;
}
</style>

评分：三段式结构齐全（2 分）；<script setup> 中用 ref 定义数据、computed 计算过滤（3 分）；<template> 用 v-model、v-for、:key（2 分）；<style scoped> 存在（1 分）。代码需可运行，语法正确。
