一、学习导读

1.1 本节定位

本节进入组件化开发，先理解为什么需要组件、如何判断拆分边界，再学习如何拆分组件、用 props/emits 实现父子通信。这是构建复杂应用的核心能力。

1.2 先修基础

先修知识 程度 说明
第 2~6 次课 必须 SFC、响应式、指令、列表渲染

1.3 学习目标

  • ✅ 掌握组件注册
  • ✅ 掌握 props 与 emits
  • ✅ 掌握父子通信
  • ✅ 了解组件 v-model
  • ✅ 理解组件化对维护、复用和协作的价值
  • ✅ 能根据业务边界判断是否拆分组件

1.4 学习前先回答三个问题

为什么需要组件？

当页面变复杂时，把视图、状态和交互封装成可复用单元，才能控制修改范围，而不是在一份越来越长的文件里寻找影响。

什么时候应该拆？

出现重复、独立状态、清晰业务名词或独立加载/错误状态时，拆分通常能降低认知负担；不是按文件行数机械切割。

拆分后如何协作？

父组件拥有业务状态，子组件通过 props 接收输入、通过 emits 发送意图，组件之间用明确契约协作。

二、知识点详解

知识点 K7-0：为什么需要组件与拆分决策

1. 组件是什么：可复用的界面单元

组件不是“把 HTML 再包一层”的技巧，而是一个有边界、有输入、有输出的界面单元。它可以同时拥有自己的模板、样式、响应式状态和事件处理逻辑，并通过公开的接口与外部协作。

可以把组件理解成一个小型函数：props 是输入，emits 是输出，模板和内部状态是实现细节。父组件只关心“给它什么”和“它发生了什么”，不需要知道子组件内部每一个按钮如何实现。

图示 1：页面从一整块代码演化为可协作的组件
阶段 1

单体页面

所有模板、请求、筛选、表单和弹窗都堆在一个 App.vue 中，开始很快，变化后很难定位影响。

→
阶段 2

按职责分块

把筛选栏、列表项、弹窗等有独立职责的部分提取出来，父组件保留页面编排和核心状态。

→
阶段 3

契约化协作

每个组件通过 props/emits 交流，能够单独阅读、测试、替换，也更适合多人并行开发。

2. Vue组件的重要性

Vue 的响应式和模板语法解决了“数据变化后如何更新视图”，组件进一步解决了“功能变多后如何组织代码”。组件化的价值不只在于复用，更在于给代码建立可理解的边界。

价值没有组件时使用组件后带来的结果
复用相似结构复制多份，修改容易漏改同一个组件接收不同 props一次修复，多处受益
隔离变化改一个弹窗可能影响整页模板组件内部实现隐藏在边界后降低回归风险
降低认知负担阅读页面需要同时理解所有细节先看组件名和接口，再按需深入更容易读懂和接手
团队协作多人同时修改同一个大文件，冲突多按业务组件拆分任务和目录并行开发更顺畅
测试与复盘只能从整页操作验证，定位失败原因慢可单独验证输入、输出和边界状态问题定位更快
性能边界所有内容常常一起加载和更新可配合异步组件、缓存和局部更新为性能优化留下空间

注意：组件化不会自动带来性能提升。它首先是一种组织复杂度的方式；只有当组件边界与真实业务边界匹配，并配合合理的渲染策略时，才可能同时获得性能收益。

3. 什么情况需要拆分成组件

拆分的依据是职责和变化边界，不是“每 50 行拆一个文件”。下面的信号越多同时出现，越值得提取组件：

1
重复出现
同一块卡片、表单项、提示框在两个页面出现，或同一页面通过 v-for 重复渲染时，优先提取成可配置组件。
2
有独立状态或交互
组件拥有展开/收起、校验、分页、加载中、错误提示等内部状态，并且这些状态不需要父组件逐一管理。
3
能说出清晰的业务名词
如果一段代码可以被准确称为“课程筛选栏”“地址选择器”“订单摘要”，它通常已经具备独立边界。
4
有独立的加载、错误或权限状态
例如用户列表和统计图加载节奏不同，拆开后可分别处理 skeleton、空状态和权限提示。
5
变化节奏不同
页面布局由一个人维护，但支付按钮由另一个团队频繁迭代，拆分可以减少互相牵连。
6
需要单独测试或复用
一段逻辑需要在多个场景验证，或者未来明确会在多个页面使用，提前建立组件接口通常更划算。

4. 组件不是越多越好：哪些情况先不要拆

建议拆分

  • 重复的结构和交互已经出现两次以上。
  • 子区域有明确名称，输入和输出可以写成接口。
  • 子区域需要单独处理加载、错误、校验或权限。
  • 父组件只负责编排，子组件可以专注一个变化原因。

暂不拆分

  • 只有一个简单的 <span> 或两三行静态文字。
  • 拆分后需要传递大量 props，再层层转发事件。
  • 子组件没有独立职责，只是把父组件的代码原样搬走。
  • 页面仍在快速探索，接口还没有稳定的业务含义。

一个实用原则是：先让页面能表达业务，再根据重复、职责和变化边界提取组件。好的组件会减少沟通成本；为了“看起来组件很多”而拆分，反而会增加接口和跳转成本。

5. 不拆分与拆分的对比：成本和收益

比较维度全部写在 App.vue按职责拆分如何取舍
首次开发文件少，写起来直接需要规划目录和接口一次性小页面可先不拆
重复使用复制粘贴，容易出现分叉通过 props 配置差异有第二个使用场景就重新评估
修改影响依赖隐含在同一文件中边界和影响面更清晰长期维护页面优先拆分
通信成本可以直接访问同一作用域变量需要设计 props/emits接口是成本，也是可见的约束
测试定位失败时需要从整页排查可以定位到具体组件和状态交互复杂、风险高时优先拆分

6. 详细示例：课程商城页从单体到组件化

下面用一个“课程商城”演示完整决策过程。页面有搜索课程、展示课程卡片、加入学习计划和购物车汇总四个职责。它足够小，便于课堂演示，又包含真实项目中常见的输入、输出和状态归属问题。

6.1 不拆分的单体写法

<!-- App.vue：搜索、列表、课程卡片、购物车全部混在一起 -->
<template>
  <main class="course-shop">
    <h2>课程商城</h2>
    <input v-model.trim="keyword" placeholder="搜索课程" />
    <p>已选 {{ cart.length }} 门</p>

    <ul>
      <li v-for="course in filteredCourses" :key="course.id">
        <strong>{{ course.name }}</strong>
        <span>¥{{ course.price }}</span>
        <button @click="addToCart(course)">加入学习计划</button>
      </li>
    </ul>

    <footer>合计：¥{{ total }}</footer>
  </main>
</template>

<script setup>
import { computed, ref } from 'vue'

const keyword = ref('')
const courses = ref([
  { id: 1, name: 'Vue 组件基础', price: 49 },
  { id: 2, name: 'Vue Router 实战', price: 59 },
  { id: 3, name: 'Pinia 状态管理', price: 69 }
])
const cart = ref([])
const filteredCourses = computed(() => courses.value.filter(course =>
  course.name.includes(keyword.value)
))
const total = computed(() => cart.value.reduce((sum, item) => sum + item.price, 0))
const addToCart = (course) => {
  if (!cart.value.some(item => item.id === course.id)) cart.value.push(course)
}
</script>

6.2 单体写法的问题

  1. 职责混杂：搜索输入、列表渲染、课程卡片样式和购物车计算都由同一个组件负责。
  2. 复用困难：如果后台管理页也需要课程卡片，只能复制模板并接受后续分叉。
  3. 修改风险集中：调整卡片按钮可能触碰筛选或购物车逻辑，评审时不容易看出影响范围。
  4. 状态归属不清：哪些数据是页面业务状态，哪些只是卡片内部状态，没有清楚边界。

6.3 先画组件树，再写代码

图示 2：课程商城组件树与职责边界
  • App.vue 页面状态与业务编排
    • CourseFilter.vue 输入关键词，展示已选数量
    • CourseList.vue 接收课程数组，转发选择事件
      • CourseCard.vue 展示单门课程，发出 add 意图
    • CartSummary.vue 接收已选课程，计算并展示合计

这里没有把每个标签都拆出来：App.vue 保留页面级数据和业务决策，CourseCard.vue 只关心一门课程的展示与“加入”意图。组件边界服务于职责，而不是追求文件数量。

6.4 拆分后的核心代码

父组件 App.vue：拥有状态，负责组合。

<template>
  <main class="course-shop">
    <h2>课程商城</h2>
    <CourseFilter v-model="keyword" :count="cart.length" />
    <CourseList :courses="filteredCourses" @select="addToCart" />
    <CartSummary :items="cart" />
  </main>
</template>

<script setup>
import { computed, ref } from 'vue'
import CourseFilter from './components/CourseFilter.vue'
import CourseList from './components/CourseList.vue'
import CartSummary from './components/CartSummary.vue'

const keyword = ref('')
const cart = ref([])
const courses = ref([
  { id: 1, name: 'Vue 组件基础', price: 49 },
  { id: 2, name: 'Vue Router 实战', price: 59 },
  { id: 3, name: 'Pinia 状态管理', price: 69 }
])
const filteredCourses = computed(() => courses.value.filter(course =>
  course.name.includes(keyword.value)
))
const addToCart = (course) => {
  if (!cart.value.some(item => item.id === course.id)) cart.value.push(course)
}
</script>

子组件 CourseFilter.vue：用 v-model 暴露输入，用 props 接收只读信息。

<template>
  <div class="course-filter">
    <input
      :value="modelValue"
      placeholder="搜索课程"
      @input="emit('update:modelValue', $event.target.value)"
    />
    <span>已选 {{ count }} 门</span>
  </div>
</template>

<script setup>
defineProps({
  modelValue: { type: String, default: '' },
  count: { type: Number, default: 0 }
})
const emit = defineEmits(['update:modelValue'])
</script>

子组件 CourseList.vue：只负责列表循环，把事件向上转发。

<template>
  <ul>
    <CourseCard
      v-for="course in courses"
      :key="course.id"
      :course="course"
      @add="emit('select', $event)"
    />
  </ul>
</template>

<script setup>
import CourseCard from './CourseCard.vue'
defineProps({ courses: { type: Array, default: () => [] } })
const emit = defineEmits(['select'])
</script>

子组件 CourseCard.vue：只关心一门课程和用户点击。

<template>
  <li class="course-card">
    <strong>{{ course.name }}</strong>
    <span>¥{{ course.price }}</span>
    <button @click="emit('add', course)">加入学习计划</button>
  </li>
</template>

<script setup>
defineProps({
  course: { type: Object, required: true }
})
const emit = defineEmits(['add'])
</script>

子组件 CartSummary.vue：接收数据并派生展示值，不直接修改父状态。

<template>
  <footer>已选 {{ items.length }} 门，合计：¥{{ total }}</footer>
</template>

<script setup>
import { computed } from 'vue'
const props = defineProps({ items: { type: Array, default: () => [] } })
const total = computed(() => props.items.reduce((sum, item) => sum + item.price, 0))
</script>

6.6 组件拆分检查清单

A
先写一句职责
能否用“它负责……”说清组件唯一的主要职责？说不清时先不要创建文件。
B
列出输入和输出
把需要的 props、要发出的 emits 写在纸上；如果接口比实现还复杂，说明边界可能不合适。
C
确认状态归属
跨组件共享且决定业务结果的状态放在共同父级；只服务于自身视觉交互的状态留在子组件。
D
检查是否真的复用
复用不只是“出现两次”，还包括未来是否会以不同数据、不同场景使用；没有稳定差异就不要过早参数化。

课堂结论：组件化的目标不是让目录看起来更碎，而是让每个变化有明确的归属。先找业务边界，再设计 props/emits；当组件只剩下转发和拼接时，应重新审视是否拆得过细。

知识点 K7-1：组件基础与注册

定义

组件是可复用的 Vue 实例，把页面拆成独立可维护的单元。组件化就是把复杂页面拆成多个组件组合。

注册方式

局部注册（推荐，<script setup> 下）：

<!-- 父组件 App.vue -->
<template>
  <div>
    <HelloWorld msg="Hi" />      <!-- 直接使用 -->
  </div>
</template>
<script setup>
import HelloWorld from './components/HelloWorld.vue'   <!-- 导入即用，无需注册 -->
</script>

全局注册（main.js，少用）：

import { createApp } from 'vue'
import App from './App.vue'
import MyComp from './MyComp.vue'
const app = createApp(App)
app.component('MyComp', MyComp)   // 全局注册，任意地方可用
app.mount('#app')

组件命名

  • PascalCase（推荐）：HelloWorld，模板用 <HelloWorld /> 或 <hello-world />。
  • kebab-case：hello-world。
  • <script setup> 中 import 的组件名即使用名。

易错点

  • 全局注册过多组件：全局注册的组件无法 Tree-shaking，增大体积，优先局部注册。
  • 组件名与 HTML 原生标签冲突：避免用 header/footer 等原生标签名作组件名（用 PascalCase 区分）。

小结

组件化拆分页面；<script setup> 下 import 即用（局部注册，推荐）；全局注册用 app.component。

知识点 K7-2：props

定义

props 是父组件传给子组件的数据，子组件用 defineProps 声明接收。props 是单向数据流，子组件不应直接修改。

用法

<!-- 子组件 UserInfo.vue -->
<template>
  <div>
    <p>姓名：{{ props.name }}</p>
    <p>年龄：{{ props.age }}</p>
  </div>
</template>
<script setup>
// 使用对象声明：带类型、默认值、必填和校验
const props = defineProps({
  name: { type: String, required: true },
  age: { type: Number, default: 18 },
  status: { type: String, validator: (v) => ['active', 'inactive'].includes(v) }
})
</script>
<!-- 父组件 App.vue -->
<template>
  <UserInfo name="张三" :age="20" status="active" />
</template>
<script setup>
import UserInfo from './UserInfo.vue'
</script>

props 校验

选项 说明
type 类型：String/Number/Boolean/Array/Object/Function 等
required: true 必填
default 默认值（对象/数组需用工厂函数 () => []）
validator 自定义校验函数

单向数据流

props 从父流向子，子组件不能直接修改 props。若需基于 props 派生数据，用 computed 或本地 ref 拷贝。

易错点

  • 子组件直接改 props：Vue 警告，应 emit 通知父改。
  • 对象/数组默认值直接写：default: [] 报错，应 default: () => []。
  • 解构 props 丢失响应式：const { name } = props 后 name 不响应式，需用 toRefs。

小结

props 父传子，单向数据流，子不能直接改；用 defineProps 声明类型/默认/必填/校验。

知识点 K7-3：emits

定义

emits 是子组件向父组件传递数据的方式，子组件用 defineEmits 声明，用 $emit（或返回的函数）触发事件，父组件用 @事件名 监听。

用法

<!-- 子组件 Counter.vue -->
<template>
  <button @click="increment">+1 ({{ count }})</button>
</template>
<script setup>
import { ref } from 'vue'
const props = defineProps({ init: { type: Number, default: 0 } })
const emit = defineEmits(['change'])          // 声明事件
const count = ref(props.init)
const increment = () => {
  count.value++
  emit('change', count.value)                  // 触发事件，传数据
}
</script>
<!-- 父组件 App.vue -->
<template>
  <Counter :init="0" @change="onChange" />
</template>
<script setup>
import Counter from './Counter.vue'
import { ref } from 'vue'
const result = ref(0)
const onChange = (val) => { result.value = val }   // 接收子组件数据
</script>

易错点

  • 忘声明 emits：<script setup> 中不声明也能用，但声明后更清晰且能校验，推荐声明。
  • 事件名用驼峰：推荐用 kebab-case（'change'/'update:value'），模板监听用 @change。

小结

emits 子传父：子用 defineEmits 声明 + emit 触发；父用 @事件名 监听接收数据。

知识点 K7-4：父子组件通信综合

定义

父子通信是组件化开发的核心：父传子用 props，子传父用 emits，形成数据流动闭环。

通信方案

方向 方式 说明
父 → 子 props 父传数据给子
子 → 父 emits 子触发事件，父监听
跨层 provide / inject 祖先传后代（后续课程）
全局 状态管理（Pinia） 第 12 次课

综合示例

易错点

  • 用 props 反向传数据：props 只能父传子，子传父必须 emit。

小结

父传子 props，子传父 emits；跨层用 provide/inject，全局用状态管理。

知识点 K7-5：组件 v-model

定义

组件 v-model 是父子组件双向绑定的语法糖，让组件像表单元素一样支持 v-model。

原理

<Child v-model="x" /> 等价于：

<Child :modelValue="x" @update:modelValue="x = $event" />

即：父传 modelValue（props），子 emit update:modelValue 通知父更新。

用法（Vue 3.4+ 推荐 defineModel）

<!-- 子组件 MyInput.vue -->
<template>
  <input :value="model" @input="model = $event.target.value" />
</template>
<script setup>
// Vue 3.4+：defineModel 是编译器宏，无需 import
const model = defineModel()              // 自动声明 modelValue + update:modelValue
</script>
<!-- 父组件 -->
<template>
  <MyInput v-model="text" />            <!-- 双向绑定 -->
  <p>{{ text }}</p>
</template>
<script setup>
import { ref } from 'vue'
import MyInput from './MyInput.vue'
const text = ref('')
</script>

多个 v-model

<Child v-model:title="t" v-model:author="a" />
<!-- 子组件用 defineModel('title')、defineModel('author') -->

易错点

  • Vue 3.4 以下无 defineModel：需手动 props: modelValue + emit('update:modelValue', val)。
  • 事件名必须 update:modelValue：v-model 默认绑定 modelValue，更新事件名固定。

小结

组件 v-model = :modelValue + @update:modelValue；Vue 3.4+ 用 defineModel 简化；支持多 v-model。

三、综合示例：CTTS-Frontend LoginForm 组件

子组件 LoginForm.vue：

<template>
  <form @submit.prevent="onSubmit">
    <input v-model.trim="form.username" placeholder="用户名" />
    <input v-model.trim="form.password" type="password" placeholder="密码" />
    <button type="submit">登录</button>
  </form>
</template>
<script setup>
import { reactive } from 'vue'
const props = defineProps({ initName: { type: String, default: '' } }) // 父传初始用户名
const emit = defineEmits(['submit'])                        // 声明事件
const form = reactive({ username: props.initName, password: '' })
const onSubmit = () => {
  emit('submit', { username: form.username, password: form.password })  // 子传父
}
</script>

父组件 App.vue：

<template>
  <div class="app">
    <LoginForm :init-name="defaultName" @submit="onLogin" />
    <p v-if="msg">{{ msg }}</p>
  </div>
</template>
<script setup>
import { ref } from 'vue'
import LoginForm from './components/LoginForm.vue'
const defaultName = ref('admin')
const msg = ref('')
const onLogin = (data) => {                                  // 接收子组件数据
  msg.value = `登录：${data.username} / ${data.password}`
}
</script>

运行方式：在 src/components/LoginForm.vue 与 src/App.vue 分别创建，npm run dev 提交表单，父组件显示登录信息。注意 props 用 kebab-case 传递（init-name）。
