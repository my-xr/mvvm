二、知识点详解

知识点 K11-1：全局守卫

定义

全局守卫对所有路由跳转生效，分前置 beforeEach 与后置 afterEach。前置守卫常用于登录拦截。

用法

import { createRouter, createWebHistory } from 'vue-router'
const router = createRouter({ history: createWebHistory(), routes })

// 全局前置守卫
router.beforeEach((to, from) => {
  // to: 目标路由；from: 来源路由
  // 返回 false 取消；返回路径/对象 重定向；不返回或 true 放行
  const isLogin = localStorage.getItem('token')
  if (to.meta.requireAuth && !isLogin) {
    return '/login'           // 重定向到登录页
  }
  // 不返回 = 放行
})

// 全局后置守卫（不能改变导航，常用于埋点、改标题）
router.afterEach((to) => {
  document.title = to.meta.title || 'CTTS-Frontend'
})

Vue Router 4 的 next 说明

Vue Router 4 推荐通过返回值控制导航，不再强制 next()：

  • 不返回 / 返回 true / undefined：放行。
  • 返回 false：取消导航。
  • 返回路径字符串或路由对象：重定向。

仍可用 next 参数（兼容），但推荐返回值写法。

易错点

  • beforeEach 不返回：默认放行，需显式 return 重定向。
  • 后置守卫改导航：afterEach 不能改变导航，只能做副作用。
  • 死循环：重定向到 /login 时若 /login 也 requireAuth 会无限重定向，应排除登录页。

小结

beforeEach 前置守卫做登录拦截，通过返回值控制放行/重定向/取消；afterEach 后置做副作用。

知识点 K11-2：路由独享守卫与组件内守卫

定义

  • 路由独享守卫 beforeEnter：只在进入某条路由时触发，写在路由配置里。
  • 组件内守卫：在组件内用 onBeforeRouteLeave（离开前）、onBeforeRouteUpdate（路由更新前）。

用法

路由独享：

const routes = [
  {
    path: '/admin',
    component: Admin,
    beforeEnter: (to, from) => {
      if (localStorage.getItem('role') !== 'admin') {
        return '/login'      // 非管理员重定向
      }
    }
  }
]

组件内守卫：

<script setup>
import { onBeforeRouteLeave, onBeforeRouteUpdate } from 'vue-router'

onBeforeRouteLeave((to, from) => {
  const ok = confirm('确定离开？未保存的数据将丢失')
  if (!ok) return false      // 取消导航
})

onBeforeRouteUpdate((to, from) => {
  // 同组件不同参数（如 /user/1 → /user/2）触发
})
</script>

守卫执行顺序

图示 1：导航守卫执行顺序

导航触发

用户点击链接、调用 push，或地址栏发生变化。

beforeEach

全局前置守卫先做登录、角色等通用判断。

beforeEnter

路由独享守卫处理当前路由的专属规则。

beforeRouteEnter

组件进入前守卫处理组件级准备逻辑。

afterEach

全局后置守卫收尾，例如记录日志或设置标题。

易错点

  • 组件内守卫用错 API：Vue 3 用 onBeforeRouteLeave 组合式 API，非 beforeRouteLeave 选项。
  • beforeEnter 只对当前路由：不影响子路由（除非子路由也配置）。

小结

beforeEnter 路由独享；组件内 onBeforeRouteLeave/onBeforeRouteUpdate；守卫按全局→独享→组件内→后置顺序执行。

知识点 K11-3：路由元信息 meta

定义

路由元信息 meta 是路由配置中的自定义字段，用于存储权限、标题等信息，守卫中读取 to.meta 判断。

用法

const routes = [
  { path: '/login', component: Login, meta: { title: '登录' } },
  { path: '/projects', component: Projects, meta: { requireAuth: true, title: '项目列表' } },
  { path: '/admin/users', component: Users, meta: { requireAuth: true, role: 'admin', title: '用户管理' } }
]

router.beforeEach((to) => {
  document.title = to.meta.title || 'CTTS'
  if (to.meta.requireAuth && !localStorage.getItem('token')) {
    return '/login'
  }
  if (to.meta.role && localStorage.getItem('role') !== to.meta.role) {
    return '/projects'        // 角色不符重定向
  }
})

meta 合并

嵌套路由的 meta 会合并（子路由 meta 与父路由 meta 合并，子优先）。

易错点

  • meta 写在子路由但守卫读父：守卫中 to.meta 是合并后的结果，可直接读。
  • 把敏感信息放 meta：meta 在前端可见，不能存密钥等敏感数据，只存权限标识。

小结

meta 存储路由元信息（权限/角色/标题），守卫读取 to.meta 判断是否放行。

知识点 K11-4：路由懒加载与代码分割

定义

路由懒加载 用动态 import() 按需加载路由组件，减小首屏体积，提升加载速度。

用法

const routes = [
  { path: '/login', component: () => import('../views/Login.vue') },
  { path: '/projects', component: () => import('../views/Projects.vue') }
]

分组（chunk）

const routes = [
  {
    path: '/admin',
    component: () => import(/* webpackChunkName: "admin" */ '../views/Admin.vue')
  }
]

Vite 自动代码分割，每个动态 import 生成独立 chunk。

易错点

  • 全部静态 import：首屏加载所有组件，体积大；应用懒加载。
  • 过度拆分：每个路由一个 chunk 可能产生过多请求，可分组。

小结

路由懒加载用 () => import()，按需加载优化首屏；Vite 自动代码分割。

知识点 K11-5：重定向与 404

定义

重定向 用 redirect 字段；404 页面用通配路由 :pathMatch(.*)* 匹配所有未定义路径。

用法

const routes = [
  { path: '/', redirect: '/projects' },                    // 重定向
  { path: '/home', redirect: { name: 'projects' } },        // 命名路由重定向
  { path: '/projects', name: 'projects', component: Projects },
  { path: '/:pathMatch(.*)*', component: () => import('../views/NotFound.vue') }  // 404，放最后
]

404 注意

  • 通配路由必须放最后，否则会匹配所有路径。
  • Vue Router 4 用 :pathMatch(.*)*（Vue 2 是 *）。

易错点

  • 404 路由放前面：会匹配所有，导致其他路由失效。
  • 重定向死循环：A 重定向 B，B 又重定向 A。

小结

redirect 重定向；{ path: '/:pathMatch(.*)*', component: NotFound } 配置 404，放路由表最后。

三、综合示例：CTTS-Frontend 登录权限与角色路由

src/router/index.js：

import { createRouter, createWebHistory } from 'vue-router'
import Layout from '../views/Layout.vue'

const routes = [
  { path: '/login', component: () => import('../views/Login.vue'), meta: { title: '登录' } },
  {
    path: '/',
    component: Layout,
    meta: { requireAuth: true },
    children: [
      { path: 'projects', component: () => import('../views/Projects.vue'), meta: { title: '项目列表' } },
      { path: 'tasks/:id', component: () => import('../views/TaskDetail.vue'), props: true, meta: { title: '任务详情' } },
      { path: 'admin/users', component: () => import('../views/Users.vue'), meta: { title: '用户管理', role: 'admin' } }
    ]
  },
  { path: '/:pathMatch(.*)*', component: () => import('../views/NotFound.vue') }
]

const router = createRouter({ history: createWebHistory(), routes })

// 全局前置守卫：登录 + 角色校验
router.beforeEach((to) => {
  document.title = to.meta.title || 'CTTS-Frontend'
  const token = localStorage.getItem('token')
  const role = localStorage.getItem('role')

  if (to.meta.requireAuth && !token) {
    return '/login'                       // 未登录跳登录
  }
  if (to.meta.role && to.meta.role !== role) {
    return '/projects'                     // 角色不符
  }
})

export default router

Login.vue（登录后存 token 与 role）：

<template>
  <form @submit.prevent="onLogin">
    <input v-model="username" placeholder="用户名" />
    <input v-model="password" type="password" placeholder="密码" />
    <button type="submit">登录</button>
  </form>
</template>
<script setup>
import { ref } from 'vue'
import { useRouter } from 'vue-router'
const username = ref('')
const password = ref('')
const router = useRouter()
const onLogin = () => {
  // 简化：实际应调后端接口
  localStorage.setItem('token', 'fake-token')
  localStorage.setItem('role', 'admin')    // 实际从后端返回
  router.push('/projects')
}
</script>

运行方式：配置路由与守卫，未登录访问 /projects 会跳转 /login；登录后可访问；非 admin 访问 /admin/users 跳回 /projects。
