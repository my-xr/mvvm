一、学习导读

1.1 本节定位：谁都能进的系统

第 10 课我们做出了 CTTS 的全部页面，但有一个明显的漏洞：没登录也能看所有页面。请做一个实验：运行第 10 课的项目，在地址栏直接输入 /projects 或 /user/profile，页面照样打开。真实系统里，这些页面必须先登录，管理员页面还要限制角色。

本节围绕一个问题展开：怎样在“页面显示之前”加一道检查？5 个知识点是一条问题链：先做出最简单的登录拦截（K11-1），再把规则从代码里搬到路由配置上（K11-2），然后解决“登录后回不到原页面”的体验问题（K11-3），接着处理个别页面的特殊检查（K11-4），最后补齐出口兜底（K11-5）。

课程边界：路由懒加载在第 10 课 K10-2 已讲，Vite 会自动分包，本课不再重复。本课用 localStorage 临时保存登录状态，第 12 课学习 Pinia 后会改为统一的状态管理；真实登录需要后端接口，在第 14 课 Axios 中接入。

1.2 先修基础

先修知识程度说明
第 10 课 路由表、router-view、router-link必须本课所有守卫都挂在第 10 课的路由上
第 10 课 useRouter / useRoute、push / replace必须登录后跳转、读取回跳地址
第 10 课 动态路由与嵌套路由必须meta 在嵌套路由中会合并，要理解父子关系

1.3 学习目标

  • ✅ 能说清守卫解决什么问题，会用 beforeEach 做登录拦截并正确使用返回值
  • ✅ 会用 meta 给路由贴权限标签，让守卫按标签判断
  • ✅ 能实现“登录后回到原来想去的页面”
  • ✅ 能区分全局守卫、路由独享守卫、组件内守卫，并选择合适的一种
  • ✅ 会配置重定向与 404，并知道前端权限不等于真正的安全

二、知识点详解

知识点 K11-1：全局前置守卫 beforeEach

场景与痛点

退出登录后，在地址栏输入 /projects，页面依然显示。我们希望：没有 token 就不能进入任何页面，一律去登录页。

笨办法

在每个页面组件里加检查：

// Projects.vue、TaskDetail.vue、User.vue …… 每个都要写
onMounted(() => {
  if (!localStorage.getItem('token')) router.replace('/login')
})

问题有三个：页面有 20 个就要写 20 遍，漏一个就是漏洞；检查发生在组件挂载之后，用户会先看到页面闪一下再被踢走；检查逻辑改动要改所有文件。

核心思想

守卫就是路由前面的安检口：每一次导航在真正切换页面之前，都要先经过同一个检查函数，统一放行或拦截。

定义

router.beforeEach((to, from) => { ... }) 注册全局前置守卫，每次导航前都会执行。to 是要去的路由，from 是来源路由。通过返回值决定结果：

返回值效果
不返回 / true放行
false取消本次导航，留在原地
路径字符串或路由对象重定向到该地址

Vue Router 4 推荐用返回值，不再需要强制调用 next()。

最小示例：除登录页外都要登录

// src/router/index.js（在 createRouter 之后）
const whiteList = ['/login']      // 不需要登录就能访问的页面

router.beforeEach((to) => {
  const token = localStorage.getItem('token')
  if (!token && !whiteList.includes(to.path)) {
    return '/login'                 // 没登录：重定向到登录页
  }
  // 不返回：放行
})

预期现象：清除 localStorage 中的 token 后，在地址栏输入 /projects，会直接停在 /login，不会出现项目列表闪一下的情况。在登录页点击登录写入 token 后再访问 /projects 正常。

前后对照

逐页检查全局守卫
每个页面各写一遍写一次，覆盖所有导航
页面显示后才检查页面显示前就拦截
漏写即漏洞新页面默认受保护

应用场景与边界

  • 适合：登录拦截、全站统一的检查（维护模式、版本提示）。
  • 不适合：只有某一个页面才有的特殊逻辑，这类放到 K11-4 的独享或组件内守卫。
  • afterEach 是后置守卫，导航已完成，不能改变导航，只做收尾，例如改页面标题、统计埋点（K11-2 用到）。

易错点

  • 无限重定向：未登录一律跳 /login，如果 /login 本身也被拦截，就会循环。→ 原因：重定向后又触发一次守卫 → 做法：把登录页放进白名单。
  • 以为不返回就是拦截：不返回是放行。→ 要拦截必须显式 return false 或返回路径。
  • 在守卫里调用 useRouter：守卫函数不在组件 setup 中，直接用外面的 router 对象即可。

小结与钩子

beforeEach 是全站统一的安检口，用返回值放行、取消或重定向。但还剩一个问题：规则写成了“白名单路径数组”，页面一多，哪些要登录、哪些要管理员，全靠守卫里手写路径列表，路由表和权限规则分在两个地方，很容易对不上。下一节把规则贴到路由本身上。

知识点 K11-2：路由元信息 meta

场景与痛点

现在系统要增加“用户管理”页，只允许管理员访问；还要让每个页面的浏览器标题不同。按 K11-1 的写法，守卫里会变成：

if (to.path === '/admin/users' && role !== 'admin') return '/projects'
if (to.path === '/projects') document.title = '项目列表'
if (to.path.startsWith('/tasks')) document.title = '任务详情'
// ……每加一个页面，守卫就要多一行

路由表在一处，规则在另一处，新增页面时很容易忘记同步。

核心思想

给每条路由贴标签：路由自己说明“我需要登录”“我需要管理员”“我的标题是什么”，守卫只负责读标签、统一判断，不再记路径。

定义

meta 是路由配置里的自定义对象，可以放任意字段（如 requireAuth、role、title）。守卫中通过 to.meta 读取。

最小示例

const routes = [
  { path: '/login', component: () => import('../views/Login.vue'), meta: { title: '登录' } },
  {
    path: '/',
    component: () => import('../views/Layout.vue'),
    redirect: '/projects',
    meta: { requireAuth: true },            // 父路由贴标签：整个后台都要登录
    children: [
      { path: 'projects', component: () => import('../views/Projects.vue'), meta: { title: '项目列表' } },
      { path: 'admin/users', component: () => import('../views/Users.vue'), meta: { title: '用户管理', role: 'admin' } }
    ]
  }
]

router.beforeEach((to) => {
  const token = localStorage.getItem('token')
  const role = localStorage.getItem('role')
  if (to.meta.requireAuth && !token) return '/login'
  if (to.meta.role && to.meta.role !== role) return '/projects'   // 角色不符
})

router.afterEach((to) => {
  document.title = to.meta.title || 'CTTS-Frontend'              // 后置守卫改标题
})

预期现象：以普通用户（role 不是 admin）登录后访问 /admin/users，会被弹回 /projects；切换页面时浏览器标签标题随之变化。新增页面时，只需要在那条路由上写 meta，守卫一行不改。

前后对照

守卫里写死路径（K11-1）meta 标签（本节）
规则与路由分在两处规则就写在路由上
新增页面要同时改守卫只改路由，守卫不变
白名单 / 黑名单越来越长默认受保护，贴标签表示例外或限制

应用场景与边界

  • 适合：是否需要登录、允许哪些角色、页面标题、是否缓存页面等“与路由绑定的静态信息”。
  • 嵌套路由的 meta 会合并：to.meta 是匹配到的所有父子路由 meta 浅层合并的结果，子字段覆盖父字段，嵌套对象不会深度合并。所以父路由写一次 requireAuth，所有子页面自动受保护。
  • 不适合：存放敏感信息或会变化的数据。meta 在前端代码中完全可见，只存权限标识。

易错点

  • 在子路由找不到父路由的 meta：以为要自己去 to.matched 里找。→ 其实 to.meta 已经是合并结果，直接读即可。
  • 以为前端校验了就安全：用户可以修改 localStorage 或直接请求接口。→ 前端守卫只是体验层的拦截，真正的权限必须由后端接口校验。

小结与钩子

meta 让规则跟着路由走，守卫统一读 to.meta。但体验上还有一个坑：用户在 /tasks/5 被拦截去登录，登录成功后却被送到固定的 /projects，原来想看的任务页丢了。下一节解决它。

知识点 K11-3：登录后回跳原页面

场景与痛点

同事把 /tasks/5 的链接发给你，你没登录，被拦截到登录页。登录之后如果总是进入项目列表，你还得手动再找一遍任务 5，体验很差。

核心思想

被拦截时，把“本来想去的地址”记在登录页的网址里（查询参数），登录成功后再取出来跳回去。网址能携带信息，正是路由相对动态组件的优势（第 10 课 2.2）。

定义

这里用到两个已学过的东西：路由对象的 to.fullPath（含查询参数的完整路径）和重定向时的对象写法 { path, query }。没有新 API，是把它们组合起来。

最小示例

// 守卫：拦截时带上 redirect
router.beforeEach((to) => {
  if (to.meta.requireAuth && !localStorage.getItem('token')) {
    return { path: '/login', query: { redirect: to.fullPath } }
  }
})
<!-- Login.vue（登录成功后回跳） -->
<script setup>
import { useRoute, useRouter } from 'vue-router'

const route = useRoute()
const router = useRouter()

const login = () => {
  localStorage.setItem('token', 'fake-token')
  router.replace(route.query.redirect || '/projects')   // 有来源就回去，没有就去默认页
}
</script>

预期现象：未登录时访问 /tasks/5?keyword=vue，地址会变成 /login?redirect=%2Ftasks%2F5%3Fkeyword%3Dvue；登录后自动回到任务 5，并且 query 保留。

应用场景与边界

  • 适合：登录过期后重新登录、分享链接给未登录用户。
  • 回跳用 replace：登录页不应留在历史记录里，否则后退又回到登录页。
  • 安全提醒：回跳地址来自网址，用户可以篡改。真实项目中应只允许站内路径，这里的示例以教学为主。

易错点

  • 用 to.path 而不是 to.fullPath：query 和 hash 会丢失。
  • 登录后用 push 回跳：后退键回到登录页，已登录用户会觉得奇怪。
  • 已登录用户仍能打开登录页：可在守卫里加一条：已有 token 且 to.path === '/login' 时跳回首页。

小结与钩子

用 redirect 查询参数记录来源，登录后 replace 回去。全局守卫已经能管住“是否登录、是否有角色”，但还有一类需求它不擅长：只针对某一个页面的检查，或者用户正在编辑、离开时要确认。下一节专门处理。

知识点 K11-4：独享守卫与组件内守卫

场景与痛点

两个新需求：

  • 任务详情页的 id 必须是数字，/tasks/abc 不应进入页面。这只和这一条路由有关，写进全局守卫会让全局守卫塞满各种页面的私事。
  • 用户在任务详情页的备注框里写了内容但没保存，点击导航离开时应弹出确认。这个判断依赖组件内的数据，全局守卫拿不到。

核心思想

守卫可以放在不同的位置，离它要管的东西越近越好：全站的放全局，某条路由的放路由配置，依赖组件状态的放组件里。

定义

类型写在哪里触发时机
全局守卫 beforeEachrouter 实例每次导航
路由独享守卫 beforeEnter路由配置里进入这条路由时
onBeforeRouteLeave组件 setup 中要离开当前组件时
onBeforeRouteUpdate组件 setup 中同一组件因参数变化被复用时

最小示例

// 路由独享：只对 /tasks/:id 生效
{
  path: 'tasks/:id',
  component: () => import('../views/TaskDetail.vue'),
  props: true,
  beforeEnter: (to) => {
    if (isNaN(Number(to.params.id))) return '/projects'   // id 不是数字，回项目列表
  }
}
<!-- TaskDetail.vue：离开前确认 -->
<template>
  <section>
    <h2>任务 {{ id }}</h2>
    <textarea v-model='note' placeholder='写点备注（未保存离开会确认）'></textarea>
    <button type='button' @click="note = ''">保存（清空草稿）</button>
  </section>
</template>
<script setup>
import { ref } from 'vue'
import { onBeforeRouteLeave } from 'vue-router'

const props = defineProps({ id: { type: String, required: true } })
const note = ref('')

onBeforeRouteLeave(() => {
  if (note.value && !confirm('备注还没保存，确定离开吗？')) return false   // 取消导航
})
</script>

预期现象：访问 /tasks/abc 会被送回 /projects；在备注框输入内容后点击其他链接会弹出确认，点“取消”则留在原页，点“确定”才离开。

应用场景与边界：怎么选

需求选哪个
所有页面都要登录全局 beforeEach + meta
只有某条路由需要的检查（参数格式、特殊条件）beforeEnter
表单未保存确认、离开前释放资源onBeforeRouteLeave
同一组件参数变化（/tasks/5 → /tasks/8）要重新处理onBeforeRouteUpdate，或第 10 课用过的 watch

完整执行顺序（了解即可，遇到“守卫没触发”时用来排查）：

  1. 离开的组件：onBeforeRouteLeave
  2. 全局 beforeEach
  3. 被复用的组件：onBeforeRouteUpdate
  4. 路由配置：beforeEnter
  5. 解析异步组件（懒加载在这里下载）
  6. 全局 beforeResolve
  7. 导航确认，全局 afterEach

易错点

  • beforeEnter 在参数变化时不触发：从 /tasks/5 到 /tasks/abc 属于同一路由的参数变化，不会重新进入。→ 这类检查要用 onBeforeRouteUpdate。
  • 用错 API：Vue 3 的 <script setup> 里用组合式函数 onBeforeRouteLeave，不是选项式的 beforeRouteLeave。
  • 组件内守卫只在该组件是路由页面时有效：不是通过路由渲染的普通子组件里写不会触发。

小结与钩子

全局管全站，beforeEnter 管单路由，组件内守卫管依赖组件状态的离开与更新。守卫能拦截和跳转了，最后补上路由表的兜底：根路径打开是什么？乱输网址会怎样？守卫重定向与路由配置里的重定向有什么区别？

知识点 K11-5：重定向与 404 兜底

场景与痛点

两个现象：访问站点根路径 / 时没有对应页面；输入一个不存在的地址 /abc/xyz，控制台只有警告，页面一片空白。用户不知道发生了什么。

核心思想

路由表要给“没有明确归宿的网址”一个默认去处：重定向把一个网址改到另一个，404 兜底接住所有没匹配上的网址。

定义

  • 重定向：路由配置的 redirect 字段，可写路径，也可写命名路由对象。
  • 404 兜底：通配路由 /:pathMatch(.*)*，匹配所有未定义的路径。

最小示例

const routes = [
  { path: '/', redirect: '/projects' },                       // 静态重定向
  { path: '/home', redirect: { name: 'projects' } },          // 按路由名重定向
  { path: '/projects', name: 'projects', component: () => import('../views/Projects.vue') },
  { path: '/:pathMatch(.*)*', component: () => import('../views/NotFound.vue') }   // 404，放最后
]

预期现象：访问 / 与 /home 都会进入项目列表，地址栏变成 /projects；访问 /abc/xyz 显示 404 页面，页面里可以用 route.fullPath 显示用户输入的地址。

应用场景与边界

路由配置的 redirect守卫里的重定向
判断条件固定，不看状态可以看登录状态、角色等运行时信息
典型用途根路径、旧地址改新地址、父路由默认子页登录拦截、角色不符

易错点

  • 404 路由放在前面：它能匹配所有路径，后面的路由全部失效。→ 必须放路由表最后。
  • 写成 Vue 2 的 *：Vue Router 4 要写 /:pathMatch(.*)*。
  • 重定向循环：A 重定向到 B，B 又重定向到 A。→ 画出重定向链检查一遍。

小结

redirect 处理固定的默认去处，通配路由兜底 404 且放最后；需要看运行时状态的跳转交给守卫。至此，CTTS 有了入口、权限和兜底，下面把它们整合起来。

三、综合示例：CTTS 登录与权限

3.1 从第 10 课项目继续

本例在第 10 课的 ctts-router 项目上改造（已安装 vue-router@4）。第 10 课的 main.js 和 App.vue 不变；用 3.2 的内容覆盖 router/index.js 和相关页面。目标是同时验证：登录拦截、meta 权限、角色限制、登录回跳、离开确认、独享守卫、重定向与 404。

  1. 覆盖 3.2 中的文件，执行 npm run dev。
  2. 未登录直接访问 /tasks/5：应跳到登录页，且地址带 redirect 参数。
  3. 点击“以普通用户登录”：应回到任务 5；访问 /admin/users 被弹回项目列表。
  4. 退出登录，点击“以管理员登录”：可以访问用户管理页。
  5. 在任务页备注框输入内容后点击其他链接：出现离开确认。
  6. 访问 /tasks/abc、/abc/xyz、/：分别验证独享守卫、404、重定向。

3.2 文件结构与完整代码

src/
├─ App.vue          （同第 10 课：只有 router-view）
├─ main.js          （同第 10 课：.use(router)）
├─ router/
│  └─ index.js      （本课核心）
└─ views/
   ├─ Login.vue
   ├─ Layout.vue
   ├─ Projects.vue
   ├─ TaskDetail.vue
   ├─ Users.vue
   └─ NotFound.vue

src/router/index.js：

import { createRouter, createWebHistory } from 'vue-router'

const routes = [
  { path: '/login', component: () => import('../views/Login.vue'), meta: { title: '登录' } },
  {
    path: '/',
    component: () => import('../views/Layout.vue'),
    redirect: '/projects',
    meta: { requireAuth: true },
    children: [
      { path: 'projects', component: () => import('../views/Projects.vue'), meta: { title: '项目列表' } },
      {
        path: 'tasks/:id',
        component: () => import('../views/TaskDetail.vue'),
        props: true,
        meta: { title: '任务详情' },
        beforeEnter: (to) => {
          if (isNaN(Number(to.params.id))) return '/projects'
        }
      },
      { path: 'admin/users', component: () => import('../views/Users.vue'), meta: { title: '用户管理', role: 'admin' } }
    ]
  },
  { path: '/:pathMatch(.*)*', component: () => import('../views/NotFound.vue'), meta: { title: '页面不存在' } }
]

const router = createRouter({ history: createWebHistory(), routes })

router.beforeEach((to) => {
  const token = localStorage.getItem('token')
  const role = localStorage.getItem('role')

  if (to.meta.requireAuth && !token) {
    return { path: '/login', query: { redirect: to.fullPath } }   // 未登录：去登录并记住来源
  }
  if (to.meta.role && to.meta.role !== role) {
    return '/projects'                                           // 角色不符
  }
  if (to.path === '/login' && token) {
    return '/projects'                                           // 已登录不再进登录页
  }
})

router.afterEach((to) => {
  document.title = to.meta.title || 'CTTS-Frontend'
})

export default router

五、本节小结与知识结构图

图示 1：本课问题链
K11-1

全局前置守卫

没登录也能进？在导航前统一安检，用返回值放行或重定向。

K11-2

路由元信息 meta

规则散在守卫里？让路由自己带标签，守卫读 to.meta。

K11-3

登录后回跳

登录后回不去原页面？用 redirect 查询参数记住来源。

K11-4

独享与组件内守卫

个别页面的检查？守卫放在离需求最近的位置。

K11-5

重定向与 404

没有归宿的网址？redirect 给默认去处，通配路由兜底。

要点一句话
前置守卫beforeEach((to, from) => ...)，不返回放行，false 取消，路径重定向
后置守卫afterEach 不能改导航，用于改标题、埋点
meta存权限、角色、标题，嵌套路由浅层合并，守卫读 to.meta
回跳拦截时带 query.redirect = to.fullPath，登录后 replace 回去
守卫位置全局管全站，beforeEnter 管单路由，组件内守卫管离开与更新
兜底redirect 处理固定去处，404 通配路由放最后
安全边界前端守卫只是体验层拦截，真正的权限由后端校验
