二、知识点详解

知识点 K1-1：前端开发演进

定义

前端开发演进指 Web 前端从”用原生 JavaScript 直接操作 DOM”到”使用框架进行数据驱动开发”的发展过程，大致经历了三个阶段：原生 JS 阶段 → jQuery 阶段 → MVVM 框架阶段。

原理

驱动演进的根本动力是前端复杂度不断上升。页面从”静态展示”变成”复杂交互应用”后，直接操作 DOM 的方式越来越力不从心。

前端开发方式演进
阶段 1

原生 JS

直接操作 DOM，代码繁琐且容易出错。

→
阶段 2

jQuery

封装 DOM 操作，写法更短，但仍是命令式更新。

→
阶段 3

MVVM 框架

数据驱动视图，开发者主要维护状态与业务逻辑。

三个阶段对比：

阶段 代表技术 核心方式 痛点
原生 JS document.getElementById 直接操作 DOM 繁琐、易错、难维护
jQuery $().val()、$.ajax 封装 DOM 操作、链式调用 仍是命令式操作 DOM，状态一多就乱
MVVM 框架 Vue / React / Angular 数据驱动视图，声明式开发 学习成本上升，但可维护性大幅提升

问题 / 场景

问：原生 JS 操作 DOM 到底痛在哪？ 看一段原生 JS 实现”输入框搜索过滤列表”的代码：

// 原生 JS：搜索过滤
const input = document.getElementById('searchInput');
const list = document.getElementById('list');
const items = ['任务一', '任务二', '任务三'];

function renderList(keyword) {
  list.innerHTML = '';                       // 1. 先清空
  items
    .filter(item => item.includes(keyword))  // 2. 过滤
    .forEach(item => {                       // 3. 再逐个创建 DOM
      const li = document.createElement('li');
      li.textContent = item;
      list.appendChild(li);
    });
}

input.addEventListener('input', e => renderList(e.target.value));
renderList('');

痛点在于：数据和视图混在一起，每次数据变化都要手动”清空 → 重建 DOM”。一旦列表复杂（含状态、分页、嵌套），代码迅速失控。

问：框架怎么解决？ 用 Vue，同样的功能只需要：

<template>
  <input v-model="keyword" placeholder="搜索" />
  <ul>
    <li v-for="item in filteredItems" :key="item">{{ item }}</li>
  </ul>
</template>

开发者只管”数据是什么”，视图怎么更新交给框架。这就是数据驱动。

完整示例代码

下面是一段对比示例，体现”原生 JS 命令式”与”Vue 声明式”的差异（Vue 代码现在看不懂没关系，第 3 次课会详细讲，这里只需感受差异）：

<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8" />
  <title>原生 JS vs Vue 对比</title>
</head>
<body>
  <h2>原生 JS 写法（命令式）</h2>
  <div id="native-box">
    <input id="native-input" type="text" placeholder="输入名字" />
    <p id="native-tip"></p>
  </div>

  <hr />

  <h2>Vue 写法（声明式，数据驱动）</h2>
  <div id="vue-app"></div>

  <!-- 引入 Vue 3（仅用于演示对比，正式项目用 Vite） -->
  <script src="https://unpkg.com/vue@3/dist/vue.global.js"></script>
  <script>
    // ===== 原生 JS：手动监听、手动更新 DOM =====
    const nativeInput = document.getElementById('native-input');
    const nativeTip = document.getElementById('native-tip');
    nativeInput.addEventListener('input', (e) => {
      nativeTip.textContent = '你好，' + e.target.value;  // 手动更新 DOM
    });

    // ===== Vue 3：只改数据，视图自动更新 =====
    const { createApp, ref } = Vue;
    createApp({
      setup() {
        const name = ref('');
        return { name };
      },
      template: `
        <input v-model="name" placeholder="输入名字" />
        <p>你好，{{ name }}</p>
      `
    }).mount('#vue-app');
  </script>
</body>
</html>

运行方式：把上面代码保存为 compare.html，双击用浏览器打开即可。两个输入框功能相同，但 Vue 版本不需要手动操作 DOM。

易错点

  • 误以为 jQuery 也是 MVVM 框架。jQuery 只是封装了 DOM 操作，本质上仍是命令式，没有”数据驱动”。
  • 误以为框架万能。框架提升了开发效率与可维护性，但理解原生 JS 仍是基础（面试也常考原生）。
  • 把”演进”理解成”淘汰”。原生 JS 和 jQuery 并未完全消失，简单页面用它们依然合适；框架适合复杂应用。

小结

前端演进的核心是从”操作 DOM”走向”操作数据”。框架（如 Vue）让开发者专注于业务数据，视图由框架自动维护，从而大幅提升复杂应用的开发效率与可维护性。

知识点 K1-2：MVVM 架构思想

定义

MVVM（Model-View-ViewModel）是一种前端架构思想，把应用分为三部分：

  • Model（模型）：数据，如商品列表、任务信息、用户输入的内容。
  • View（视图）：用户看到的界面，即 HTML 页面。
  • ViewModel（视图模型）：连接 Model 与 View 的桥梁，负责把数据变化同步到视图，并把用户输入或事件处理结果更新回数据。

原理

更准确地说，MVVM 的核心不是“所有内容都双向绑定”，而是数据绑定与响应式同步：

MVVM 数据绑定与响应式同步（Vue 场景）
Model

响应式数据

任务、商品数量、表单值等应用状态。

ViewModel

Vue 绑定与协调层

组件实例 / setup 逻辑，负责响应式追踪、计算、事件处理与状态写入。

View

界面与交互

模板渲染出的页面，以及输入框、按钮等交互控件。

状态变化 响应式更新视图
用户输入 / 点击 事件 / v-model 回写数据
关键：View 与 Model 不直接相连；数据驱动视图、交互回写数据都经过 ViewModel。普通展示多是“数据 → 视图”，表单场景常用 v-model。

💡 关键认知：在 MVVM 中，开发者主要操作的是 Model（数据），而不是 DOM。这是与原生 JS 的本质区别。

问题 / 场景

问：MVVM 和 MVC 有什么关系？ MVC（Model-View-Controller）是更早的架构，Controller 负责处理逻辑。MVVM 是 MVC 的演进，用 ViewModel 替代 Controller，并引入数据绑定、响应式更新和表单场景的双向绑定等机制，让数据变化与界面交互可以自动协同，减少手动更新代码。前端因为频繁交互，MVVM 比 MVC 更合适。

问：ViewModel 在 Vue 中具体是什么？ 在 Vue 中，Vue 实例/组件本身就是 ViewModel。你写的 <script setup> 里的响应式数据就是 Model，<template> 就是 View，Vue 框架充当 ViewModel 完成绑定。

完整示例代码

下面用 Vue 3 演示一个”购物车数量加减、总价自动计算”的 MVVM 例子（体现数据驱动视图，以及用户操作回写数据）：

<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8" />
  <title>MVVM 示例：购物车</title>
  <script src="https://unpkg.com/vue@3/dist/vue.global.js"></script>
</head>
<body>
  <div id="app">
    <!-- View：界面 -->
    <h2>商品：{{ product.name }}</h2>
    <p>单价：¥{{ product.price }}</p>
    <p>
      数量：
      <button @click="product.count--">-</button>
      {{ product.count }}
      <button @click="product.count++">+</button>
    </p>
    <p>总价：¥{{ totalPrice }}</p>
  </div>

  <script>
    const { createApp, reactive, computed } = Vue;
    createApp({
      setup() {
        // Model：数据
        const product = reactive({ name: 'Vue3 实战书', price: 50, count: 1 });
        // 当 count 变化，totalPrice 自动重算（数据驱动）
        const totalPrice = computed(() => product.price * product.count);
        return { product, totalPrice };
      }
    }).mount('#app');
  </script>
</body>
</html>

运行方式：保存为 mvvm.html，浏览器打开。点击加减按钮，数量和总价会自动变化——你没有写一行操作 DOM 的代码，这就是 MVVM 的力量。

说明：上面用 CDN 方式引入 Vue 仅为演示方便。正式项目用 Vite 创建（见 K1-5），不要用 CDN。

保存页面所需的核心状态，不直接操作 DOM。

  • product.name：商品名称
  • product.price：商品单价
  • product.count：购买数量

连接数据与界面：处理点击事件、修改数量，并用 computed 自动计算总价。

  • 显示数量：{{ product.count }}
  • 显示总价：{{ totalPrice }}
数据 → 视图：修改 product.count 后，Vue 响应式系统触发重新计算，页面自动显示新的数量与总价。
视图 → 数据：用户点击按钮并不是 View 直接改 Model，而是通过 @click 进入 ViewModel，再更新响应式数据。

易错点

  • 把 ViewModel 理解成某个具体文件。ViewModel 是一种”角色/职责”，在 Vue 中由 Vue 框架 + 组件承担，不是某个单独的文件。
  • 以为双向绑定 = 所有数据都双向。双向绑定通常用于表单输入（v-model）；很多场景是单向的（数据→视图）。第 5 次课会详细区分。
  • 认为 MVVM 就不用写任何 DOM。框架内部仍在操作 DOM，只是替你做了；少数场景（如直接操作第三方库）仍可能用到 ref 获取 DOM（后续课程）。

小结

MVVM 通过 ViewModel 桥接 Model 与 View，实现数据与视图的自动同步。其核心价值是让开发者聚焦于数据，而非 DOM 操作，这是现代前端框架的思想基石。

知识点 K1-3：Vue 3 简介与核心特性

定义

Vue（发音 /vjuː/，同 view）是一套用于构建用户界面的渐进式 JavaScript 框架，由华人尤雨溪（Evan You）于 2014 年创建并开源。Vue 3 是其当前主版本，于 2020 年正式发布，是本课程的主框架。

原理

Vue 3 的”渐进式”含义：可以按需逐步引入功能——只用核心做视图渲染也行，配上 Router/Pinia 做完整 SPA 也行，不强求一次性全用。这降低了上手门槛。

Vue 3 相比 Vue 2 的核心改进：

特性 说明
Composition API 新的代码组织方式，把相关逻辑写在一起，更适合复杂组件复用
<script setup> 更简洁的单文件组件写法，减少样板代码
Proxy 响应式 用 ES6 Proxy 替代 Vue 2 的 Object.defineProperty，能监测新增/删除属性，性能更好
性能提升 包体积更小、渲染更快、Tree-shaking 支持更好
TypeScript 支持 源码用 TS 重写，对 TS 支持更友好（本课程用 JS，TS 可选拓展）
生态升级 Vue Router 4、Pinia（替代 Vuex）、Vite 构建工具

问题 / 场景

问：尤雨溪是谁？为什么提他？ 尤雨溪是美籍华人，曾任职于 Google（Angular 团队），后独立创建 Vue 并全职维护。Vue 是目前全球三大前端框架（Vue/React/Angular）之一，是少数由华人独立发起并成为全球主流的开源项目，体现中国开发者在开源世界的影响力。

问：Vue、React、Angular 该学哪个？ 三者都是主流框架。Vue 上手友好、文档优秀、国内使用率极高；React 生态最大、海外用得多；Angular 适合大型企业应用。本课程选 Vue 3，既因生态成熟，也因国内就业市场对 Vue 需求量大。

问：Composition API 和 Options API 是什么关系？ - Options API（Vue 2 风格）：用 data/methods/computed 等选项组织代码。 - Composition API（Vue 3 推荐）：用 setup 函数 + ref/reactive 等组合式 API，把相关逻辑聚在一起，便于复用。 - 本课程以 Composition API + <script setup> 为主线（业界当前推荐写法）。

完整示例代码

对比 Options API 与 Composition API（功能相同：一个计数器）：

<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8" />
  <title>Options API vs Composition API</title>
  <script src="https://unpkg.com/vue@3/dist/vue.global.js"></script>
</head>
<body>
  <div id="app"></div>

  <script>
    const { createApp, ref } = Vue;

    // ===== Options API（Vue2 风格，Vue3 仍支持） =====
    const OptionsComp = {
      data() { return { count: 0 }; },
      methods: { add() { this.count++; } },
      template: `
        <div>
          <h4>Options API</h4>
          <p>计数：{{ count }}</p>
          <button @click="add">+1</button>
        </div>
      `
    };

    // ===== Composition API（Vue3 推荐） =====
    const CompositionComp = {
      setup() {
        const count = ref(0);
        const add = () => count.value++;
        return { count, add };
      },
      template: `
        <div>
          <h4>Composition API</h4>
          <p>计数：{{ count }}</p>
          <button @click="add">+1</button>
        </div>
      `
    };

    createApp({
      components: { OptionsComp, CompositionComp },
      template: `
        <OptionsComp />
        <hr />
        <CompositionComp />
      `
    }).mount('#app');
  </script>
</body>
</html>

运行方式：保存为 api-compare.html，浏览器打开。两种写法效果一样，但 Composition API 把 count 和 add 放在一起，逻辑更聚合（复杂组件优势更明显）。<script setup> 是更简化的写法，第 2 次课讲。

Vue 3 生态全景（本课程涉及部分）：

Vue 3 生态全景

Vue 3 核心

响应式 + 组件 + 模板

Vue Router 4负责路由导航与页面切换
Pinia负责全局状态管理
Vite负责开发服务器与项目构建
Axios负责网络请求与接口联调

组合使用共同支撑完整 Vue SPA 项目

易错点

  • 混淆 Vue 2 与 Vue 3。两者 API 风格不同（Options vs Composition），响应式原理不同（defineProperty vs Proxy）。本课程统一用 Vue 3，避免混用。
  • 以为”渐进式”= 功能少。渐进式指”可按需引入”，不代表功能弱；Vue 全家桶可支撑大型 SPA。
  • 把 Composition API 和 <script setup> 等同。<script setup> 是 Composition API 的语法糖（更简洁写法），两者是包含关系。

小结

Vue 3 是尤雨溪创建的渐进式前端框架，核心特性包括 Composition API、<script setup>、Proxy 响应式与性能提升。本课程以 Composition API + <script setup> 为主线，配合 Vite、Vue Router 4、Pinia、Axios、Element Plus 构建完整 SPA。

知识点 K1-4：Node.js 与 npm

定义

  • Node.js：一个基于 V8 引擎的 JavaScript 运行时，让 JavaScript 能脱离浏览器、在服务器/本机上运行。前端工程化工具（如 Vite）都是用 Node.js 运行的。
  • npm（Node Package Manager）：Node.js 的包管理工具，用于安装、管理第三方库（称为”包”或”依赖”），也是发布自己包的平台。

原理

浏览器中的 JS 与 Node.js 中的 JS

浏览器中的 JavaScript

主要操作页面 DOM、响应用户事件、发起网络请求。

Node.js 中的 JavaScript

运行命令行工具、读写文件、启动开发服务器、管理工程依赖。

在前端开发中，Node.js 不是用来”写后端”的（虽然它能写），而是用来运行前端工程化工具：Vite、Webpack、ESLint 等都是 Node.js 程序。所以搭前端环境必须先装 Node.js。

npm 的工作流程：

npm 安装依赖流程
1在 package.json 中声明项目依赖
2执行 npm install 下载依赖
3依赖进入 node_modules 目录
4通过 npm run dev 等脚本运行工具

问题 / 场景

问：装了 Node.js 就有 npm 了吗？ 是的。npm 随 Node.js 一起安装，装完 Node.js 后在终端执行 npm -v 能看到版本号，说明 npm 也就绪了。

问：npm、yarn、pnpm 有什么区别？ 三者都是包管理工具。npm 是官方自带；yarn、pnmm 是第三方替代，速度更快。本课程统一用 npm，学懂后切换 yarn/pnpm 很容易。后续也可选用 pnpm。

问：为什么国内安装很慢，怎么解决？ npm 默认从官方仓库（国外）下载，国内访问慢。解决方法是切换为国内镜像（如淘宝镜像）：

# 设置 npm 镜像为淘宝源（永久生效）

# 验证
npm config get registry

易错点

  • 以为 Node.js 是后端框架。Node.js 是运行时，能写后端但不是框架；前端开发用它来运行工具。
  • Node 版本过低。Vue 3 + Vite 要求 Node.js 20.19+ 或 22.12+。版本过低会报各种奇怪错误，先查 node -v。
  • 混淆全局安装与项目安装。npm install -g xxx 是全局安装（装到本机），npm install xxx 是项目安装（装到当前项目的 node_modules）。Vite 项目依赖用项目安装即可。
  • 误删 node_modules。node_modules 是依赖目录，删了要重新 npm install；它通常很大，不纳入版本控制（用 .gitignore 排除）。

小结

Node.js 是 JS 运行时，npm 是包管理工具，二者是前端工程化的基础。开发 Vue 3 项目前必须安装 Node.js（20.19+ 或 22.12+）并配置好 npm 镜像。后续所有命令都基于它们运行。

知识点 K1-5：Vite 创建 Vue3 项目

定义

Vite（发音 /viːt/，同 veet）是尤雨溪团队开发的新一代前端构建工具，特点是开发服务器启动极快、热更新（HMR）几乎瞬时。本课程用它来创建和构建 Vue 3 项目。

脚手架（Scaffold）指自动生成项目初始结构的工具。Vite 提供了 npm create vite@latest 命令，交互式生成一个可运行的 Vue 3 项目骨架。

原理

传统构建工具（如 Webpack）启动时要把所有模块打包后再启动服务器，项目一大就慢。Vite 利用浏览器原生 ES 模块（ESM），按需加载：启动时几乎不打包，请求到哪个模块才编译哪个，所以启动极快。

问题 / 场景

问：为什么选 Vite 而不是 Vue CLI？ Vue CLI 是 Vue 2 时代的官方脚手架（基于 Webpack），Vue 3 时代官方推荐用 Vite。Vite 启动快、配置简单、体验好，是新项目首选。本课程统一用 Vite。

问：npm create 和 npm install 有什么区别？ - npm create vite@latest：用 Vite 脚手架生成项目文件（一次性）。 - npm install：根据项目里的 package.json 下载依赖到 node_modules（每次克隆新项目都要执行一次）。

问：npm run dev 和 npm run build 区别？ - npm run dev：启动开发服务器，支持热更新，开发时用。 - npm run build：把项目打包构建成静态文件（在 dist 目录），部署时用。第 16 次课讲部署。
