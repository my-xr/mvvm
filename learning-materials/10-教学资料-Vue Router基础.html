一、学习导读

1.1 本节定位

第 8 课我们学了动态组件：<component :is> 能根据一个变量切换显示的组件。很多同学会问：既然这样就能做“多个页面”，为什么还要学 Vue Router？

本节就沿着这个问题展开：先用动态组件做一个多页面应用，亲手撞上它的局限，再看 Vue Router 如何解决。后面的 5 个知识点，都是把这个“动态组件版”逐步改造成“路由版”。

课程边界：本课覆盖基础路由、动态参数和嵌套路由；导航守卫、路由元信息和权限控制放在第 11 课。示例均按 Vue 3 + Vite + <script setup> 编写，综合案例提供完整文件，可直接创建项目运行。

1.2 先修基础

先修知识程度说明
第 7 课 组件与 props必须路由页面本质上就是组件，参数可以通过 props 传入
第 8 课 动态组件与 keep-alive必须本节的出发点，用来对比 router-view
第 4 课 响应式（ref、watch）必须路由对象是响应式的，参数变化要用 watch 监听

1.3 学习目标

  • ✅ 能说清动态组件与 Vue Router 的区别，并判断一个场景该用哪个
  • ✅ 理解“网址 ↔ 组件”的映射思想，会安装并配置 Vue Router 4
  • ✅ 会用 router-view / router-link 搭建页面导航
  • ✅ 会用 useRouter 跳转、用 useRoute 读取参数
  • ✅ 会配置动态路由（详情页）与嵌套路由（公共布局）

二、从动态组件到路由：为什么需要 Vue Router

2.1 用动态组件做多页面

假设我们要做 CTTS 系统的两个页面：“项目列表”和“个人中心”。用第 8 课的知识，写法如下：

<!-- App.vue（动态组件版） -->
<template>
  <nav>
    <button type='button' @click="current = 'projects'">项目列表</button>
    <button type='button' @click="current = 'user'">个人中心</button>
  </nav>
  <keep-alive>
    <component :is='views[current]' />
  </keep-alive>
</template>
<script setup>
import { ref } from 'vue'
import Projects from './views/Projects.vue'
import UserCenter from './views/UserCenter.vue'

const views = { projects: Projects, user: UserCenter }
const current = ref('projects')   // 当前显示哪个页面，由这个变量决定
</script>

核心机制：变量 current 决定显示哪个组件。这个方案能跑，也确实实现了“点击切换页面”。

2.2 动态组件撑不住的地方

请真的运行上面的代码，然后依次做下面几个动作，观察会发生什么：

你的操作实际结果根本原因
切到“个人中心”后按 F5 刷新回到“项目列表”当前页面只存在于内存变量 current 中，刷新即丢失
把地址栏链接发给同学对方打开永远是首页地址栏始终不变，网址里没有页面信息
点击浏览器“后退”按钮直接退出本站，而不是回到上一页切换没有产生浏览器历史记录
想做“任务 5 的详情页”要自己加 taskId 变量，再层层 props 传递没有“带参数的页面”这个概念
页面增加到 20 个views 对象和按钮越来越长，全挤在 App.vue“页面 ↔ 变量值”的对应关系要全部手写、手动维护

总结一句话：动态组件只解决了“换一个组件显示”，没有解决“页面”应有的这些能力：有自己的网址、能刷新保持、能收藏分享、能前进后退、能带参数。

2.3 路由的思路：网址驱动组件

Vue Router 的改进很直接：不再用自己定义的变量来决定显示哪个组件，而是用浏览器地址栏中的网址来决定，并由路由表统一维护“网址 → 组件”的对应关系。

图示 1：动态组件 与 Vue Router 的驱动方式
动态组件

变量 current 的值
→ views[current]
→ <component :is> 渲染

VS
Vue Router

地址栏 URL
→ 路由表 routes 匹配
→ <router-view> 渲染

因为网址本身就是页面的“身份证”，所以刷新、收藏、分享、前进后退都自然成立：只要网址对，页面就对。可以把 <router-view> 理解为“由网址驱动的 <component :is>”。

2.4 两者对比与应用场景

对比维度动态组件 <component :is>Vue Router
切换依据自己定义的变量（如 current）浏览器地址栏的 URL
地址栏不变随页面变化（如 /tasks/5）
刷新页面状态丢失，回到初始组件仍停留在当前页面
前进 / 后退无历史记录，后退会离开本站每次导航产生历史记录，可前进后退
分享 / 收藏做不到复制网址即可
传递参数手动 props、事件、共享变量路径参数 :id、查询参数 ?keyword=
多层页面结构自己写嵌套逻辑嵌套路由 children
组件缓存外包 keep-alive默认切走即销毁，需要时同样可包 keep-alive
代码规模增长页面越多，手写映射越乱集中在路由表，页面再多也清晰

应用场景怎么选？看一个问题：这次切换的结果，值不值得拥有自己的网址？

适合用动态组件适合用 Vue Router
页面内部的标签页内容（如详情页里的“概览 / 评论 / 记录”）登录页、项目列表、任务详情等整页切换
表单分步向导的各步骤用户希望刷新后仍停留在当前页
按数据类型渲染不同组件（动态表单、消息卡片）需要分享链接、收藏、从外部直接进入某页
仪表盘里切换小部件有公共布局（顶栏 + 侧栏）、有层级页面
切换状态不需要被记住、不需要网址后续要做登录拦截、权限控制（第 11 课）

二者不是替代关系，而是分工：路由负责“整个应用有哪些页面”，动态组件负责“某个页面内部怎么局部切换”。真实项目里经常同时出现：一个路由页面里再放一组用动态组件实现的标签页。

2.5 前端路由是怎么做到不刷新的

传统网站（后端路由）每换一个网址，浏览器都向服务器请求一个新的 HTML 页面，整页刷新。单页应用（SPA）只加载一次 HTML，之后由 JS 拦截网址变化，只替换页面中的组件，不再请求新页面。

对比后端路由前端路由（SPA）
谁来匹配网址服务器浏览器中的 JS（Vue Router）
切换页面请求新 HTML，整页刷新替换组件，不刷新
体验有白屏闪烁接近桌面应用，切换流畅

浏览器有两种办法改网址而不触发请求，对应 Vue Router 的两种模式：

模式URL 形式原理特点
hashhttp://x.com/#/projects改 # 后面的部分，浏览器不会发请求；监听 hashchange带 #，兼容性好，部署无需额外配置
historyhttp://x.com/projects用 HTML5 的 history.pushState 改地址，监听 popstate网址干净；部署时服务器必须把未知路径回退到 index.html

三、知识点详解

下面的 5 个知识点沿着同一条线：把 2.1 的动态组件版逐步改造成路由版，每一步都对应前面暴露的一个痛点。

知识点 K10-1：安装并改造第一个路由

场景与痛点

回到 2.2 的实验：动态组件版的页面刷新就丢、不能分享、不能后退。根源是“当前页”只存在内存变量里。

核心思想

让网址来决定显示哪个组件，由路由器维护“网址 → 组件”的对应关系。

定义

createRouter 创建路由器；routes 是网址与组件的对应表；createWebHistory 选择网址模式（见 2.5）；app.use(router) 把路由器接入应用。

步骤 1：安装

npm install vue-router@4

步骤 2：创建路由表（取代 views 对象和 current 变量）

// src/router/index.js
import { createRouter, createWebHistory } from 'vue-router'
import Projects from '../views/Projects.vue'
import UserCenter from '../views/UserCenter.vue'

const routes = [
  { path: '/projects', component: Projects },   // 网址 /projects 显示 Projects
  { path: '/user', component: UserCenter }      // 网址 /user 显示 UserCenter
]

const router = createRouter({
  history: createWebHistory(),   // history 模式；hash 模式用 createWebHashHistory()
  routes
})

export default router

对照 2.1：views = { projects: Projects, user: UserCenter } 变成了 path 与 component 的对应，只是“键”从自定义字符串换成了网址。

步骤 3：在应用中挂载

// src/main.js
import { createApp } from 'vue'
import App from './App.vue'
import router from './router'

createApp(App).use(router).mount('#app')

步骤 4：改写 App.vue

<!-- App.vue（路由版） -->
<template>
  <nav>
    <router-link to='/projects'>项目列表</router-link>
    <router-link to='/user'>个人中心</router-link>
  </nav>
  <router-view />
</template>

新旧写法对照：

动态组件版路由版
<button @click="current = 'user'"><router-link to='/user'>
<component :is='views[current]' /><router-view />
const current = ref(...)不再需要，地址栏就是“当前页”

改完再做一次 2.2 的实验：刷新、后退、复制网址，现在都正常了。需要保证 src/views/Projects.vue 和 UserCenter.vue 两个文件存在，例如：

<!-- src/views/Projects.vue -->
<template><h2>项目列表</h2></template>

应用场景与边界

  • 适合：需要多个“整页”、希望刷新保持、可以分享链接的单页应用。
  • 模式选择：内部系统、不方便改服务器配置时用 hash；对外网站、要干净网址时用 history 并配置回退。
  • 边界：只是页面内部的局部切换（如标签页），不需要网址，用动态组件即可（见 2.4）。

易错点

  • 忘记 .use(router)：router-view、router-link 都无法识别。
  • history 模式部署后刷新 404：服务器要把所有路径回退到 index.html（开发服务器已自动处理）。
  • 切换 hash 模式要改两处：导入和 history 选项都改为 createWebHashHistory。

小结与钩子

createRouter 创建路由、routes 描述“网址 → 组件”、.use(router) 挂载；router-view 取代 <component :is>，router-link 取代手写按钮。但还剩一个问题：这里只有两个页面，随手写的小数组就够了；页面一多，怎样把路由表组织清楚？router-link 又和普通 <a> 有什么不同？下一节解决。

知识点 K10-2：路由表、router-view 与 router-link

场景与痛点

K10-1 只有两个页面。页面增多后，需要一个清晰的地方登记所有页面；导航还不能用普通链接，否则整页刷新、状态全丢。

核心思想

路由表像通讯录，登记“网址 → 页面”；router-view 是相框，当前页挂在里面；router-link 是不刷新的超链接。

定义：三个核心角色

角色作用类比
routes 路由表每项 path + component，登记所有页面通讯录
<router-view>出口：匹配到的组件渲染在这里相框
<router-link>导航链接，改网址但不刷新超链接

为什么不用普通的 <a> 标签？

<a href='/user'> 会让浏览器向服务器重新请求页面，整个应用被重新加载，状态全部丢失，SPA 的意义就没了。<router-link> 拦截点击，只更新网址和对应组件。

router-link 常用属性

属性说明
to目标路径，如 '/user'（对象写法见 K10-3）
replace替换当前历史记录，不新增一条
自动 class当前所在链接会自动带 router-link-active（精确匹配时还有 router-link-exact-active），可用 CSS 做高亮
 
<router-link to='/projects'>项目列表</router-link>

路由懒加载

{ path: '/user', component: () => import('../views/UserCenter.vue') }

写成函数 + import()，页面第一次访问时才下载。思路与第 8 课的 defineAsyncComponent 相同，只是路由已经内置了支持，直接写函数即可。

应用场景与边界

  • 站内页面跳转一律用 router-link；它渲染成真正的链接，支持右键新标签打开。
  • 站外网址仍用普通 <a>。
  • 懒加载适合页面多、体积大的项目；页面很少时直接 import 也可以。

易错点

  • 忘写 <router-view>：网址变了但页面没内容。
  • path 漏写开头的 /：顶层路由的 path 应以 / 开头（嵌套子路由除外，见 K10-5）。

小结与钩子

routes 登记页面，router-view 显示页面，router-link 导航；页面组件推荐懒加载。但还剩一个问题：router-link 只能“点链接”，登录成功后自动跳转这类发生在代码里的跳转怎么做？当前网址里的信息又怎么读？下一节解决。

知识点 K10-3：useRouter 与 useRoute

场景与痛点

用户点击“登录”按钮后，要先判断账号是否正确，成功才进入项目列表。这是代码里的条件跳转，router-link 做不到。另外，页面常常需要读取当前网址里的信息（如搜索关键词）。

核心思想

useRouter 像遥控器，用来“去哪里”；useRoute 像当前位置的路牌，用来“现在在哪、带了什么信息”。

定义

  • useRouter()：拿到路由器，做动作（push / replace / back）。
  • useRoute()：拿到当前路由，读信息（path / params / query）。

用法：登录后跳转

<!-- Login.vue -->
<template>
  <section>
    <h2>登录</h2>
    <button type='button' @click='login'>登录</button>
    <button type='button' @click='router.back()'>返回上一页</button>
    <p>当前路径：{{ route.path }}</p>
  </section>
</template>
<script setup>
import { useRouter, useRoute } from 'vue-router'

const router = useRouter()   // 用来跳转
const route = useRoute()     // 用来读取当前路由

const login = () => {
  // 登录页不应该能“后退”回来，所以用 replace
  router.replace('/projects')
}
</script>

跳转时还可以附带查询参数：router.push({ path: '/projects', query: { keyword: 'vue' } }) 对应网址 /projects?keyword=vue，目标页面用 route.query.keyword 读取。声明式写法同理：<router-link :to="{ path: '/projects', query: { keyword: 'vue' } }">。查询参数不需要在路由表里声明，适合筛选、搜索、分页。路径里的参数（如 /tasks/5）是下一节的主题。

push 与 replace

  • push：新增一条历史记录，可以后退（普通跳转）。
  • replace：替换当前记录，不能后退回来（登录成功、重定向等场景）。

应用场景与边界

  • useRouter：登录成功后跳转、保存后返回列表、按条件跳转、router.back() 返回上一页。
  • useRoute：读取筛选关键词、显示当前路径、根据当前路由高亮菜单。
  • 边界：单纯的“点一下去某页”用 router-link 更合适，不要全部写成按钮加 push。

易错点

  • 混淆两者：useRouter 是“动作”，useRoute 是“数据”。
  • 在 setup 之外调用：二者必须在 setup 同步阶段调用，不能放进点击回调里才调用。
  • 解构 route：const { params } = useRoute() 会丢失响应式，应通过 route.params 访问。

小结与钩子

useRouter 用于代码里跳转，useRoute 用于读取当前网址信息；route 是响应式的，网址变了模板自动更新。但还剩一个问题：任务有成百上千个，难道给每个任务都写一条路由？下一节用动态路由，让一条路由匹配一类网址。

知识点 K10-4：动态路由与参数

场景与痛点

回到 2.2 的痛点：任务有成百上千个，难道给每个任务都写一条路由？用动态组件则要自己维护 taskId 变量并层层传递。动态路由让一条路由匹配一类网址。

核心思想

路由表里写模板，网址里填具体值，像填空题：/tasks/:id 是题目，/tasks/5 是答案。

定义

路径中以 : 开头的片段是参数占位。/tasks/:id 能匹配 /tasks/5、/tasks/8，其中 id 的值可从 route.params.id 取到。

// src/router/index.js
const routes = [
  {
    path: '/tasks/:id',
    component: () => import('../views/TaskDetail.vue'),
    props: true   // 把 params.id 作为 id 这个 prop 传给组件
  }
]
<!-- TaskDetail.vue -->
<template>
  <section>
    <h2>任务详情</h2>
    <p>任务 ID：{{ id }}</p>
    <p>任务名称：{{ title }}</p>
  </section>
</template>
<script setup>
import { ref, watch } from 'vue'

const props = defineProps({ id: { type: String, required: true } })
const title = ref('')
const tasks = { 5: '学习路由', 8: '完成导航练习' }   // 模拟数据

// 同一个组件在 /tasks/5 与 /tasks/8 之间切换时不会重建，要监听 id 变化
watch(() => props.id, (id) => {
  title.value = tasks[id] || '任务不存在'
}, { immediate: true })
</script>

应用场景与边界

适合“同一种页面、不同数据”的详情页，如任务详情、用户资料、文章页。如果两个页面结构本身不同，就应分别配置路由，不要硬用一个动态路由。

params 与 query

类型网址示例定义方式适合
路径参数 params/tasks/5路由 path 中写 :id标识“是哪一个”资源（必需）
查询参数 query/projects?keyword=vue无需预先声明，跳转时附带筛选、搜索、分页（可选）

两种取参方式

  • props: true（推荐）：参数变成 props，组件不依赖路由，便于复用和测试。
  • useRoute：直接读 route.params.id，写法简单。

URL 参数默认都是字符串，需要数值时请显式转换。

易错点

  • 参数名不一致：路由里写 :id，就必须读 params.id。
  • 参数变化页面不更新：从 /tasks/5 到 /tasks/8 复用同一组件实例，生命周期不会重走，要用 watch 监听参数。
  • 多个动态段：/users/:userId/posts/:postId，分别取 params.userId、params.postId。

小结与钩子

一条动态路由匹配一类网址；params 是必需标识，query 是可选条件；推荐 props: true，并注意用 watch 响应参数变化。但还剩一个问题：项目、任务、用户中心这些页面都要有同样的顶部标题和导航，难道每个页面都复制一遍？下一节用嵌套路由共享外壳。

知识点 K10-5：嵌套路由

场景与痛点

真实应用中，多个页面共享同一个外壳：顶部标题、导航栏始终不变，只有中间内容在换；“个人中心”内部还有“资料 / 修改密码”两个子页面。用动态组件需要自己层层嵌套判断，嵌套路由则直接用 children 描述这种父子关系。

核心思想

像相框里再嵌一个相框：父页面负责外壳，子页面只填充中间的内容。

定义

在父路由里用 children 配置子路由；父组件中放一个 <router-view> 作为子页面的出口。

const routes = [
  {
    path: '/user',
    component: () => import('../views/User.vue'),
    children: [
      { path: '', redirect: '/user/profile' },   // 访问 /user 时自动进入资料页
      { path: 'profile', component: () => import('../views/UserProfile.vue') },
      { path: 'password', component: () => import('../views/ChangePassword.vue') }
    ]
  }
]
<!-- User.vue（父页面） -->
<template>
  <section>
    <h2>用户中心</h2>
    <nav>
      <router-link to='/user/profile'>资料</router-link>
      <router-link to='/user/password'>修改密码</router-link>
    </nav>
    <router-view />   <!-- 子路由在这里渲染 -->
  </section>
</template>

路径拼接规则

  • 子路由 path 不以 / 开头：相对路径，拼接在父路径后（/user + profile = /user/profile）。
  • 子路由 path 以 / 开头：绝对路径，不与父路径拼接。

应用场景与边界

  • 适合：后台系统的公共布局（顶栏 + 侧栏）、个人中心下的多个子页、设置页的多个标签。
  • 不适合：页面之间没有共同外壳时，用平级路由即可，不要为了嵌套而嵌套。
  • 与动态组件的分工：子页面有独立网址就用嵌套路由，仅页内局部切换仍用动态组件。

易错点

  • 父组件忘写 <router-view>：子页面无处渲染。
  • 想拼接却给子 path 加了 /：变成绝对路径，拼接失效。

小结与钩子

children 描述父子页面，父组件里的 router-view 显示子页面；子 path 不以 / 开头则与父路径拼接。但还剩一个问题：现在所有页面谁都能直接进入，没登录也能看项目列表。第 11 课用导航守卫解决。

import { createRouter, createWebHistory } from 'vue-router'

const routes = [
  { path: '/login', component: () => import('../views/Login.vue') },
  {
    path: '/',
    component: () => import('../views/Layout.vue'),
    redirect: '/projects',
    children: [
      { path: 'projects', component: () => import('../views/Projects.vue') },
      { path: 'tasks/:id', component: () => import('../views/TaskDetail.vue'), props: true },
      {
        path: 'user',
        component: () => import('../views/User.vue'),
        children: [
          { path: '', redirect: '/user/profile' },
          { path: 'profile', component: () => import('../views/UserProfile.vue') },
          { path: 'password', component: () => import('../views/ChangePassword.vue') }
        ]
      }
    ]
  },
  { path: '/:pathMatch(.*)*', component: () => import('../views/NotFound.vue') }
]

const router = createRouter({
  history: createWebHistory(),
  routes
})

export default router
