三、组件拆分决策

3.1 为什么需要组件

组件不是“把一个文件切成很多文件”这么简单。它把模板、状态、事件和样式封装成一个有明确输入输出的单元。拆分后，父组件负责组合和业务状态，子组件负责一个局部职责；同一个子组件可以在列表、详情页或不同练习中复用。

  • 可维护：修改状态标签只需要改一个组件，不必在多个页面搜索重复 HTML。
  • 可复用：TaskSummaryCard 接收数据即可生成三张不同的统计卡片。
  • 可测试：可以单独验证子组件的 props、事件和边界状态。
  • 可协作：不同成员可以按组件边界开发，不互相覆盖整页模板。

3.2 拆分与不拆分对比

不拆分（短期能显示，长期难维护）：把三张统计卡片全部写在父组件中，结构和文字重复。

<!-- ComponentBasicPractice.vue：不推荐的重复写法 -->
<div class="summary-card">待完成任务：{{ pendingCount }}</div>
<div class="summary-card">已提交成果：{{ submittedCount }}</div>
<div class="summary-card">平均得分：{{ averageScore }}</div>

这段代码的问题是：卡片布局、图标、帮助文字要改三次；将来新增第四张卡片还要继续复制；不同页面无法直接复用。

拆分后（本项目的做法）：父组件只维护数据并循环，子组件只负责一张卡片。

<!-- 父组件 -->
<TaskSummaryCard
  v-for="card in summaryCards"
  :key="card.label"
  v-bind="card"
/>

<!-- TaskSummaryCard.vue -->
<template>
  <article class="component-mini-card">
    <strong>{{ icon }}</strong>
    <div><p>{{ label }}</p><b>{{ value }}</b><small>{{ help }}</small></div>
  </article>
</template>
<script setup>
defineProps({
  icon: String,
  label: { type: String, required: true },
  value: { type: [String, Number], required: true },
  help: String
})
</script>

3.3 拆分判断清单

问题回答“是”时的建议本项目例子
是否在两个位置出现相同结构？抽为可复用组件，输入差异通过 props 传入。TaskSummaryCard
是否有独立状态或交互？抽出组件，让它管理局部状态并通过 emit 报告结果。TaskRow 的“查看任务”
是否需要单独测试或替换？设置清晰的输入/输出边界。SubmissionEditor
是否只有一行、只使用一次且没有独立逻辑？可以先留在父组件，避免过度拆分。简单的静态说明文字

组件过大时难以定位问题，组件过碎时阅读成本变高。最终依据是职责、复用价值和变更边界，不是文件数量越多越好。

四、实验所需关键知识

知识点 K9-1：props 与 emits 的单向数据流

父组件通过 props 把数据传给子组件，子组件不能直接修改 props；子组件通过 emit 派发事件，父组件决定如何修改自己的状态。以任务行练习为例：

<!-- 父组件 ParentChildPractice.vue -->
<TaskRow :task="task" @select-task="handleSelectTask" />

<script setup>
import TaskRow from './TaskRow.vue'
function handleSelectTask(selectedTask) {
  // 父组件收到子组件派发的任务对象
  console.log(selectedTask)
}
</script>
<!-- 子组件 TaskRow.vue -->
<script setup>
const props = defineProps({ task: { type: Object, required: true } })
const emit = defineEmits(['select-task'])
function selectTask() {
  emit('select-task', props.task)
}
</script>

<template>
  <button type="button" @click="selectTask">查看任务</button>
</template>

注意：defineProps 和 defineEmits 是 <script setup> 编译宏，不需要从 vue 导入。事件名要完全对应：子组件 emit('select-task')，父组件监听 @select-task。

知识点 K9-2：provide / inject

什么时候使用

当数据需要跨越多层组件传递，而中间组件并不使用它时，可以由祖先 provide，后代 inject。它适合主题、表单上下文、当前用户等“同一组件树共享”的依赖；不应把所有业务状态都藏进注入上下文，复杂全局状态仍应考虑明确的状态管理方案。

图示 2：同一组件树中的 provide / inject 依赖流
1 · 祖先组件

Provider：provide

提供响应式 theme、currentUser 和更新方法。

2 · 中间层

Layout：不需要传 props

中间组件只负责布局，不声明、不接收、不转发自己不用的上下文。

3 · 后代组件

Consumer：inject

后代按同一个 key 注入，直接读取共享状态并调用祖先提供的方法。

祖先 provide → 同一组件树 → 后代 inject；只要仍在这棵组件树中，依赖就能跨过任意层级。

最小可运行示例：响应式主题上下文

// src/injectionKeys.js
export const THEME_KEY = Symbol('ctts-theme')
<!-- App.vue 或其他祖先组件 -->
<script setup>
import { provide, readonly, ref } from 'vue'
import { THEME_KEY } from './injectionKeys'

const theme = ref('light')
function toggleTheme() {
  theme.value = theme.value === 'light' ? 'dark' : 'light'
}
provide(THEME_KEY, {
  theme: readonly(theme), // 后代只能读，不能直接 theme.value = ...
  toggleTheme
})
</script>
<!-- 任意后代组件 ThemeBadge.vue -->
<script setup>
import { inject } from 'vue'
import { THEME_KEY } from '../injectionKeys'

const themeContext = inject(THEME_KEY)
if (!themeContext) {
  throw new Error('ThemeBadge 必须放在提供 THEME_KEY 的组件内部')
}
const { theme } = themeContext
</script>

<template>
  <div :class="['theme-badge', theme]">
    当前主题：{{ theme }}
  </div>
</template>

必须掌握的细节

  • 字符串 key（如 'theme'）容易拼写冲突；跨文件共享时优先使用 Symbol key。
  • 注入的是 ref 才能保持响应式；模板中会自动解包，脚本中仍要写 theme.value。
  • 可以传默认值：inject(THEME_KEY, 'light')；默认值很复杂时可传工厂函数并将第三个参数设为 true。
  • 如果后代需要修改状态，注入“修改方法”而不是暴露可写 ref；readonly 只能保护 ref 的直接赋值，不能替代业务权限校验。
import { inject } from 'vue'
// 第三个参数 true 表示第二个参数是“工厂函数”，需要时才创建默认值
const context = inject(THEME_KEY, () => ({ theme: 'light' }), true)

知识点 K9-3：透传 Attributes

父组件传给子组件、但没有被 defineProps 或 defineEmits 声明的属性，会进入 $attrs。它包括普通 HTML 属性、class、style 和事件监听器。单根组件默认把这些属性放到根元素；如果真正应该接收属性的是内部输入框，就要关闭自动继承并手动绑定。

<!-- BaseField.vue：把属性透传到 input，而不是外层 label -->
<script setup>
import { useAttrs } from 'vue'

defineOptions({ inheritAttrs: false })
const attrs = useAttrs()
defineProps({ label: { type: String, required: true } })
</script>

<template>
  <label class="base-field">
    <span>{{ label }}</span>
    <input v-bind="attrs" />
  </label>
</template>
<!-- 父组件使用：placeholder、disabled、aria-label、@input 都会到 input -->
<BaseField
  label="成果标题"
  placeholder="请输入标题"
  maxlength="40"
  aria-label="成果标题"
  @input="onInput"
/>
<!-- 多根节点组件：Vue 不会猜属性应该落在哪个根节点，必须明确绑定 -->
<template>
  <label>成果标题</label>
  <input v-bind="$attrs" />
</template>
  • 单根组件可以让 Vue 自动透传；多根节点组件不会自动决定放到哪一个根节点，必须显式 v-bind="$attrs"。
  • inheritAttrs: false 后如果忘记手动绑定，属性和事件会消失；如果同时自动透传和手动透传，可能出现重复绑定。
  • 已经声明的 props/emits 不会出现在 attrs 中，所以 label 仍由 defineProps 接收。
  • useAttrs() 适合传递，不要把它当成需要深度监听的响应式数据源。

知识点 K9-4：defineModel 的详细用法（Vue 3.4+）

defineModel 是 <script setup> 编译宏，通常不需要从 vue 导入。它把 prop 和 update: 事件组合成一个可直接用于 v-model 的 ref。

4.1 默认模型

<!-- TextInput.vue -->
<script setup>
const model = defineModel({
  type: String,
  default: ''
})
</script>

<template>
  <input v-model="model" />
</template>

<!-- 父组件 -->
<TextInput v-model="keyword" />

上面的写法等价于子组件声明 modelValue，并派发 update:modelValue。父组件没有初始值时，子组件的 default 可能造成短暂的父子不同步；实践中建议父组件先写 const keyword = ref('')。

4.2 多个命名模型：本项目成果编辑器

<!-- SubmissionEditor.vue（Vue 3.4+ 写法） -->
<script setup>
const title = defineModel('title', { type: String, default: '' })
const content = defineModel('content', { type: String, default: '' })
const emit = defineEmits(['submit'])
</script>

<template>
  <div class="editor-box">
    <label>成果标题
      <input v-model="title" placeholder="请输入成果标题" />
    </label>
    <label>成果说明
      <textarea v-model="content" placeholder="请描述本次提交的成果内容" />
    </label>
    <button type="button" @click="emit('submit')">提交成果</button>
  </div>
</template>
<!-- ComponentVModelPractice.vue -->
<SubmissionEditor
  v-model:title="form.title"
  v-model:content="form.content"
  @submit="submitSubmission"
/>

4.3 修饰符与 get/set 转换

<!-- TrimInput.vue：使用 v-model.capitalize 时首字母转大写 -->
<script setup>
const [model, modifiers] = defineModel({
  type: String,
  set(value) {
    if (modifiers.capitalize && value) {
      return value.charAt(0).toUpperCase() + value.slice(1)
    }
    return value
  }
})
</script>
<template><input v-model="model" /></template>

<!-- 父组件 -->
<TrimInput v-model.capitalize="name" />

get 用于读取时转换，set 用于写回父组件前转换。转换规则应保持简单且可预期，不要在 setter 中执行异步请求。

4.4 不使用 defineModel 时的等价写法

<script setup>
const props = defineProps({ title: { type: String, default: '' } })
const emit = defineEmits(['update:title'])
function updateTitle(event) {
  emit('update:title', event.target.value)
}
</script>
<template>
  <input :value="props.title" @input="updateTitle" />
</template>

如果项目必须兼容 Vue 3.3 或更早版本，使用上面的手动写法；不要把 defineModel 当作普通函数导入。确认项目的 Vue 版本后再选择方案。

任务 10：provide / inject 主题上下文

项目入口：ProvideInjectPractice.vue。祖先组件提供主题，工具栏后代读取并调用切换方法；中间的 ProvideInjectMiddle.vue 不接收任何主题 props，用来观察跨层注入。

  1. 在 src/injectionKeys.js 中使用 Symbol 创建 THEME_CONTEXT_KEY。
  2. 在 ProvideInjectPractice.vue 中用 ref('light') 保存主题，并 provide(THEME_CONTEXT_KEY, { theme: readonly(theme), toggleTheme })。
  3. 在 ProvideInjectToolbar.vue 中注入同一个 key，解构出顶层 theme 和 toggleTheme。
  4. 点击工具栏按钮，确认工具栏和摘要组件都能看到主题变化。
<!-- ProvideInjectPractice.vue 的核心 -->
<script setup>
import { provide, readonly, ref } from 'vue'
import { THEME_CONTEXT_KEY } from '../injectionKeys'

const theme = ref('light')
function toggleTheme() {
  theme.value = theme.value === 'light' ? 'dark' : 'light'
}
provide(THEME_CONTEXT_KEY, { theme: readonly(theme), toggleTheme })
</script>

<!-- ProvideInjectToolbar.vue 的核心 -->
<script setup>
import { inject } from 'vue'
import { THEME_CONTEXT_KEY } from '../injectionKeys'
const context = inject(THEME_CONTEXT_KEY)
if (!context) throw new Error('缺少主题提供者')
const { theme, toggleTheme } = context
</script>
<template>
  <button type="button" @click="toggleTheme">当前主题：{{ theme }}，切换</button>
</template>

验收：切换主题后，工具栏和摘要区域都更新；中间布局组件没有为了传值增加 props；后代不能直接修改 readonly(theme)。

任务 11：provide / inject 当前用户上下文

项目入口：继续在 ProvideInjectPractice.vue 中完成 USER_CONTEXT_KEY。主题和当前用户是两个独立依赖，使用两个 Symbol key，后代组件按需注入。

<!-- 祖先：提供当前用户和修改方法 -->
import { USER_CONTEXT_KEY } from '../injectionKeys'
const currentUser = ref({ id: 'zhang', name: '张老师', role: '指导教师' })
const users = [
  { id: 'zhang', name: '张老师', role: '指导教师' },
  { id: 'li', name: '李同学', role: '项目成员' }
]
function switchUser(id) {
  const nextUser = users.find(user => user.id === id)
  if (nextUser) currentUser.value = nextUser
}
provide(USER_CONTEXT_KEY, {
  currentUser: readonly(currentUser),
  users: readonly(users),
  switchUser
})

<!-- 后代：只注入自己需要的用户上下文 -->
const userContext = inject(USER_CONTEXT_KEY)
if (!userContext) throw new Error('缺少当前用户提供者')
const { currentUser, users, switchUser } = userContext

验收：切换下拉框用户后，ProvideInjectSummary.vue 的姓名和角色同步变化；key 拼写错误时能根据错误提示定位问题；修改用户必须调用 switchUser，不能在后代直接改只读 ref。

任务 12：Attributes 透传到字段控件

项目入口：AttrsForwardPractice.vue 和 BaseField.vue。要求把普通属性、ARIA 属性和 @input 事件落到真正的 input/textarea，而不是外层 label。

<!-- BaseField.vue -->
<script setup>
import { useAttrs } from 'vue'
defineOptions({ inheritAttrs: false })
const attrs = useAttrs()
defineProps({
  label: { type: String, required: true },
  hint: { type: String, default: '' },
  multiline: { type: Boolean, default: false }
})
</script>
<template>
  <label class="field-shell">
    <span>{{ label }}</span>
    <textarea v-if="multiline" v-bind="attrs" />
    <input v-else v-bind="attrs" />
    <small v-if="hint">{{ hint }}</small>
  </label>
</template>
<!-- 父组件：value 和 @input 也会透传给 input -->
<BaseField
  label="成果标题"
  :value="form.title"
  maxlength="40"
  placeholder="请输入成果标题"
  aria-label="成果标题"
  @input="form.title = $event.target.value"
/>

验收：在浏览器 Elements 面板确认 maxlength、placeholder、aria-label 位于内部 input；输入后父组件预览同步更新。已声明的 label 是 prop，不会进入 attrs。

任务 13：Attributes 透传到按钮并保留事件

验收：点击按钮后两个表单字段清空；检查原生 button 的属性和事件；组件本身没有复制父组件的 resetForm 业务逻辑。

任务 14：用 defineModel 重构成果编辑器

把任务 9 中的手动 defineProps + defineEmits 改为 Vue 3.4+ 的 defineModel。要求保留父组件现有用法，不修改 v-model:title、v-model:content 和 @submit。

<!-- SubmissionEditor.vue 的重构目标 -->
<script setup>

const content = defineModel('content', { type: String, default: '' })

<template>
  <div class="editor-box">

    <textarea v-model="content" placeholder="请描述本次提交的成果内容" />
    <span>{{ content.length }} 字</span>
    <button type="button" @click="emit('submit')">提交成果</button>
  </div>
</template>

验收：父组件不改代码仍可实时收到两个字段；字符数随内容变化；点击提交仍由父组件校验。若项目 Vue 版本低于 3.4，恢复任务 9 的手动写法，不要强行导入 defineModel。

问题一句话回答
为什么拆组件？封装职责、复用结构、降低修改和测试成本。
什么时候不拆？一次性、无独立状态、没有复用价值的极小片段可以留在父组件。
如何跨层共享？祖先 provide，后代 inject；响应式 ref 和 Symbol key 要保持一致。
如何让原生属性落到内部 input？关闭自动继承，再把 useAttrs() 的结果绑定到目标元素。
defineModel 做了什么？把 v-model 对应的 prop 和 update 事件封装成可写 ref。
