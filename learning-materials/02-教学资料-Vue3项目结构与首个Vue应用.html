二、知识点详解

知识点 K2-1：Vue3 项目目录结构

定义

Vite 创建的 Vue 3 项目有一套约定俗成的目录结构，每个文件/目录都有明确职责。理解结构是团队协作的基础。

原理：文件加载链路

Vue3 项目文件加载链路
HTML 外壳index.html

提供 #app 挂载点，并通过 type="module" 加载入口脚本。

JS 入口src/main.js

导入根组件，执行 createApp(App).mount('#app') 创建并挂载应用。

根组件src/App.vue

承载顶层界面，可继续导入 src/components/ 中的子组件。

完整目录与职责

CTTS-Frontend 推荐目录结构
  • ctts-frontend/
    • node_modules/ 依赖目录：npm install 生成，不手改、不提交
    • public/ 静态资源：直接拷贝，用 /xxx 访问
      • vite.svg
    • src/ 源代码主目录
      • assets/ 需构建处理的资源，通常 import 引入
        • vue.svg
      • components/ 可复用组件
      • App.vue 根组件
      • main.js 应用入口
      • style.css 全局样式
    • index.html SPA HTML 外壳
    • package.json 依赖清单与脚本命令
    • vite.config.js Vite 配置
    • .gitignore Git 忽略配置
文件/目录 职责
index.html SPA 唯一 HTML，含挂载点 #app，加载 main.js
src/main.js 创建 Vue 应用、引入根组件、挂载到 #app
src/App.vue 根组件，整个应用的顶层模板
src/components/ 存放可复用子组件
src/assets/ 需构建处理的资源（import 引入）
public/ 不需构建的静态资源（直接拷贝）
package.json 依赖清单与脚本命令
vite.config.js Vite 配置（别名、代理、插件等）

关键文件代码

index.html：

<!DOCTYPE html>
<html lang="zh-CN">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>CTTS-Frontend</title>
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.js"></script>
  </body>
</html>

src/main.js：

import { createApp } from 'vue'   // 引入 createApp
import App from './App.vue'       // 引入根组件
import './style.css'              // 引入全局样式

createApp(App).mount('#app')      // 创建应用并挂载

易错点

  • 混淆 public 与 assets：public 用绝对路径 /xx.svg 访问，不构建；assets 用 import 引入，会构建（可被 Vite 处理哈希等）。引用错位置会 404。
  • 把组件放在 src 外：组件应放 src/components/，放外面虽能跑但不规范，不利于维护。
  • 直接改 node_modules：依赖目录不要手动改，npm install 会覆盖。

小结

Vue 3 项目加载链路：index.html → src/main.js → src/App.vue。源代码集中在 src/，组件放 src/components/，资源按是否需构建分放 assets 或 public。

知识点 K2-2：SFC 单文件组件

定义

SFC（Single File Component，单文件组件） 是 Vue 的特色写法，把一个组件的结构（template）、逻辑（script）、样式（style） 写在同一个 .vue 文件中。

原理：三段式

<template>
  <!-- 结构：HTML，组件的视图 -->
</template>

<script setup>
// 逻辑：JavaScript，组件的数据与方法
</script>

<style scoped>
/* 样式：CSS，组件的外观 */
</style>

三段各自职责： | 段 | 作用 | 是否必须 | | --- | --- | --- | | <template> | 组件的 HTML 结构（视图） | 推荐，一个组件通常有 | | <script setup> | 组件的逻辑（数据、方法） | 推荐 | | <style> | 组件的样式 | 可选 |

<style scoped> 中的 scoped 表示样式只作用于当前组件，避免污染全局。

问题 / 场景

问：为什么把 HTML/JS/CSS 放一个文件？ 传统分离三文件的方式在组件化开发中反而割裂了"一个组件的完整性"。SFC 把组件相关的三部分聚合，方便维护与复用——打开一个 .vue 就能看到该组件的全部。

问：三段顺序有要求吗？ 没有强制要求，但社区约定 template → script → style。Vite 官方脚手架与 ESLint 插件也按此顺序。

完整示例代码

<!-- src/components/Hello.vue -->
<template>
  <div class="hello">
    <h2>{{ message }}</h2>
    <button @click="sayHi">点击问好</button>
  </div>
</template>

<script setup>
import { ref } from 'vue'

const message = ref('Hello, Vue 3!')
const sayHi = () => {
  alert(message.value)
}
</script>

<style scoped>
.hello {
  text-align: center;
  padding: 20px;
}
h2 {
  color: #42b883;
}
</style>

易错点

  • <template> 没有唯一根元素（Vue 2 要求）：Vue 3 支持多根节点（Fragment），但建议初学仍用单根包裹，避免样式与逻辑混乱。
  • 忘了 scoped：不加 scoped 的样式会全局生效，可能污染其他组件。组件样式建议加 scoped。
  • 在 <template> 里写 JS 逻辑：模板只放声明式绑定，复杂逻辑放 <script setup>。

小结

SFC 用三段式把组件的结构、逻辑、样式聚合在一个 .vue 文件，是 Vue 组件化开发的基本单元。

知识点 K2-3：<script setup> 语法

定义

<script setup> 是 Vue 3 推荐的 Composition API 语法糖，用于编写组件逻辑。它比普通 <script> + setup() 函数更简洁。

原理

普通 <script setup> 的特点：

  1. 顶层即 setup：整个 <script setup> 内容就是 setup 函数体，组件每次渲染时执行。
  2. 自动暴露：顶层声明的变量、函数，自动暴露给模板使用，无需 return。
  3. 导入即用：import 进来的组件/工具，可直接在模板用，无需注册。
  4. 更好的性能：编译时优化，减少运行时开销。

对比普通 setup 函数：

// 普通 <script> + setup()：需要手动 return
export default {
  setup() {
    const count = ref(0)
    const add = () => count.value++
    return { count, add }   // 必须 return 才能在模板用
  }
}
<!-- <script setup>：自动暴露，无需 return -->
<script setup>
import { ref } from 'vue'
const count = ref(0)
const add = () => count.value++
// count、add 自动可用
</script>

问题 / 场景

问：<script setup> 里能 import 组件直接用吗？ 能。导入的组件自动注册，无需 components: { } 选项：

<script setup>
import Hello from './Hello.vue'   // 导入即用
</script>
<template>
  <Hello />                        <!-- 直接用 -->
</template>

问：能用 Options API 吗？ 可以，但混用不推荐。一个组件要么全用 <script setup>，要么用普通 <script> + Options。本课程统一用 <script setup>。

完整示例代码

<template>
  <div>
    <p>计数：{{ count }}</p>
    <button @click="add">+1</button>
    <button @click="reset">重置</button>
  </div>
</template>

<script setup>
import { ref } from 'vue'

const count = ref(0)
const add = () => count.value++
const reset = () => { count.value = 0 }
</script>

图示

<script setup> 编译与使用关系
顶层声明
count、add 等变量/函数
组件导入
import Hello from './Hello.vue'
→→
模板直接可用
{{ count }}、@click="add"，无需 return
导入即注册
模板中直接写 <Hello />，无需 components 选项

易错点

  • 在 <script setup> 里写 export default：不需要也不允许，<script setup> 本身就是语法糖，不要再写 export default。
  • 以为导入的组件要注册：<script setup> 下 import 进来的组件自动可用，别再加 components。
  • 解构 props 丢失响应式（提前警示）：props 解构会丢失响应式，需用 toRefs（第 7 次课讲）。

小结

<script setup> 是 Composition API 语法糖，顶层声明自动暴露、导入即用、无需 return，是 Vue 3 推荐的组件逻辑写法。

知识点 K2-4：响应式初体验 ref

定义

ref 是 Vue 3 创建响应式数据的 API。把一个值用 ref() 包裹，这个值就变成"响应式"的——当它变化时，引用它的视图会自动更新。

原理

ref() 返回一个 Ref 对象，结构形如 { value: 原始值 }。Vue 通过追踪 .value 的读写实现响应式。

ref 响应式更新链路
ref(0)创建 Ref 对象
{ value: 0 }JS 中读写真实值
修改 .valueVue 捕获状态变化
视图自动更新模板重新渲染相关位置

关键规则：

  • 在 JavaScript 中：必须通过 .value 读写，如 count.value++。
  • 在 模板 中：自动解包（unwrap），直接用 {{ count }}，不要写 {{ count.value }}。

问题 / 场景

问：为什么 JS 里要 .value，模板里不用？ ref 返回的是对象（{value}），JS 中必须访问 .value 才能拿到真实值。模板中 Vue 自动"解包"了 ref，直接显示值，所以不用 .value。这是初学者最易错的点。

问：ref 只能包基本类型吗？ 不是。ref 也能包对象/数组，但对象一般推荐用 reactive（第 4 次课详讲）。ref 包对象时，访问属性仍需 obj.value.xxx。

完整示例代码

<template>
  <div>
    <p>访问次数：{{ visitCount }}</p>
    <button @click="visitCount++">增加访问</button>
    <button @click="reset">重置</button>
  </div>
</template>

<script setup>
import { ref } from 'vue'

const visitCount = ref(0)        // 响应式数据
const reset = () => {
  visitCount.value = 0           // JS 中必须 .value
}
// visitCount.value++  ✅ 正确
// visitCount++        ❌ 错误（visitCount 是对象，不能直接++）
</script>

图示

模板自动解包与 JS 中 .value 的区别

模板中

{{ visitCount }} 会自动解包，直接显示真实数值；点击按钮中的表达式也可像普通值一样使用。

JavaScript 中

visitCount.value++ 才是在修改 Ref 内部真实值；直接给 visitCount 重新赋值会丢失响应式。

易错点

  • JS 中忘写 .value：count++ 会报错或失效，必须 count.value++。
  • 模板中多写 .value：{{ count.value }} 会显示 undefined，模板自动解包，写 {{ count }} 即可。
  • 重新赋值整个 ref：count = ref(0) 会覆盖变量、丢失原 ref，应改 count.value = 0。
  • 在解构中丢失响应式：let { value } = count 后 value 不再响应式。

小结

ref 创建响应式数据，返回 Ref 对象。JS 中用 .value 访问，模板中自动解包。它是体验"数据驱动视图"的第一个工具。

知识点 K2-5：首个页面开发（CTTS-Frontend 首页）

定义

把 K2-1~K2-4 综合运用，开发 CTTS-Frontend 首页：欢迎信息 + 静态项目列表 + 访问计数器，体现 SFC 结构与 ref 响应式。

原理

首页结构：

CTTS-Frontend 首页结构
1
顶部：系统名称与课程/项目简介。
2
中部：项目功能列表，展示核心业务能力。
3
底部：访问计数器，使用 ref 与按钮交互完成响应式体验。

完整示例代码（直接替换 src/App.vue）

<template>
  <div class="home">
    <header class="header">
      <h1>CTTS-Frontend</h1>
      <p>校园实训任务管理系统</p>
    </header>

    <main class="main">
      <h2>实训项目列表</h2>
      <ul class="project-list">
        <li v-for="project in projects" :key="project.id" class="project-item">
          <span class="title">{{ project.title }}</span>
          <span class="status">{{ project.status }}</span>
        </li>
      </ul>

      <div class="counter">
        <p>本页访问次数：{{ visitCount }}</p>
        <button @click="visitCount++">增加访问</button>
        <button @click="resetCount">重置</button>
      </div>
    </main>
  </div>
</template>

<script setup>
import { ref } from 'vue'

// 静态项目列表数据
const projects = ref([
  { id: 1, title: '项目一：JavaWeb 后端开发', status: '进行中' },
  { id: 2, title: '项目二：Vue3 前端开发', status: '进行中' },
  { id: 3, title: '项目三：全栈联调实训', status: '未开始' }
])

// 访问计数器（响应式）
const visitCount = ref(0)
const resetCount = () => {
  visitCount.value = 0
}
</script>

  color: #999;
  font-size: 14px;
}
.counter {
  margin-top: 30px;
  text-align: center;
}
button {

运行方式：保存后 Vite 自动热更新，浏览器看到首页。点击"增加访问"按钮，访问次数自动 +1（数据驱动，无需操作 DOM）。

易错点

  • v-for 忘加 :key：列表渲染必须加唯一 key（这里用 project.id），否则 Vue 警告且影响更新性能。第 6 次课详讲。
  • projects 用普通数组而非 ref：普通数组修改后视图不更新，需用 ref（或 reactive）才是响应式。
  • {{ project.title }} 写成 {{ projects.title }}：v-for 里 project 是循环变量，注意层级。

小结

通过 CTTS-Frontend 首页，综合运用了 SFC 三段式、<script setup>、ref、v-for，初步建立"数据驱动视图"的实战直觉。
