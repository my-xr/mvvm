二、知识点详解

知识点 K12-1：Pinia 简介与对比 Vuex

定义

Pinia 是 Vue 3 官方推荐的状态管理库，是 Vuex 的继任者，更简洁、TS 友好、无 mutations。

Pinia vs Vuex

特性 Vuex Pinia
mutations 必须通过 mutations 改 state 无 mutations，直接改
模块 modules 嵌套 每个 store 独立平级
TS 支持 较弱 友好（源码 TS 重写）
体积 较大 更小
异步 actions actions（无需 mutations）
学习成本 较高 低

安装与挂载

npm install pinia
// main.js
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'
const app = createApp(App)
app.use(createPinia())
app.mount('#app')

小结

Pinia 是 Vue3 官方推荐状态管理，无 mutations、TS 友好、store 平级独立。

知识点 K12-2：defineStore 定义 store

定义

defineStore 用于定义一个 store，第一个参数是唯一 id，第二个是配置（state/getters/actions）。

用法

// src/stores/user.js
import { defineStore } from 'pinia'

export const useUserStore = defineStore('user', {
  state: () => ({
    token: '',
    userInfo: null
  }),
  getters: {
    isLogin: (state) => !!state.token
  },
  actions: {
    login(token) {
      this.token = token
    },
    logout() {
      this.token = ''
      this.userInfo = null
    }
  }
})

组合式写法（Setup Store）

import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useUserStore = defineStore('user', () => {
  const token = ref('')                       // state
  const isLogin = computed(() => !!token.value) // getters
  const login = (t) => { token.value = t }     // actions
  return { token, isLogin, login }
})

两种写法等价，选项式更易上手，组合式更灵活。

小结

defineStore('id', 配置) 定义 store；选项式（state/getters/actions）或组合式（ref/computed/函数）。

知识点 K12-3：state

定义

state 是 store 的数据源，用函数返回对象（保证每个实例独立）。

组件中读取与修改

<template>
  <p>Token：{{ userStore.token }}</p>
  <p>是否登录：{{ userStore.isLogin }}</p>
  <button @click="userStore.login('abc')">登录</button>
  <button @click="userStore.token = 'abc'">直接改</button>
</template>
<script setup>
import { useUserStore } from '../stores/user'
const userStore = useUserStore()
</script>

修改方式

  1. 直接改：userStore.token = 'abc'（Pinia 允许，不像 Vuex 需 mutation）。
  2. $patch 对象：userStore.$patch({ token: 'abc', userInfo: {...} })（批量改）。
  3. $patch 函数：userStore.$patch(state => { state.token = 'abc' })。
  4. action：userStore.login('abc')。

解构保持响应式（storeToRefs）

import { storeToRefs } from 'pinia'
const userStore = useUserStore()
const { token, isLogin } = storeToRefs(userStore)   // 解构保持响应式
// 注意：actions 解构后直接用，不需 storeToRefs
const { login } = userStore

易错点

  • 解构 state 丢失响应式：const { token } = userStore 后 token 不响应式，需 storeToRefs。
  • state 用对象而非函数：state: { token: '' } 错误，必须 state: () => ({ token: '' })。

小结

state 是数据源，用函数返回；可直接改或 $patch；解构用 storeToRefs 保持响应式。

知识点 K12-4：getters

定义

getters 是基于 state 的计算状态，类似 computed，有缓存。

用法

export const useUserStore = defineStore('user', {
  state: () => ({
    token: 'abc',
    userInfo: { name: '张三', role: 'admin' }
  }),
  getters: {
    isLogin: (state) => !!state.token,
    userName: (state) => state.userInfo?.name || '未登录',
    // 访问其他 getter（不用 state，用 this）
    greeting() {
      return `你好，${this.userName}`
    }
  }
})

组件中使用

<template>
  <p>{{ userStore.greeting }}</p>
</template>

易错点

  • getters 间互相访问：用 this（不能用箭头函数访问 this，需普通函数）。
  • getters 依赖外部数据：getters 应只依赖 state，不依赖外部变量。

小结

getters 是计算状态有缓存，类似 computed；getter 间互访用 this。

知识点 K12-5：actions

定义

actions 是 store 的方法，可同步可异步，用于封装业务逻辑（如登录请求、修改状态）。

用法

export const useUserStore = defineStore('user', {
  state: () => ({ token: '', userInfo: null }),
  actions: {
    // 同步
    setToken(token) {
      this.token = token
    },
    logout() {
      this.token = ''
      this.userInfo = null
    },
    // 异步
    async login(credentials) {
      const res = await fetch('/api/login', {
        method: 'POST',
        body: JSON.stringify(credentials)
      })
      const data = await res.json()
      this.token = data.token
      this.userInfo = data.userInfo
      return data
    }
  }
})

组件中调用

const userStore = useUserStore()
await userStore.login({ username: 'admin', password: '123' })

易错点

  • actions 中用 this：Pinia actions 用 this 访问 state/getters，不能用箭头函数（this 指向错）。
  • 异步忘 await：组件调用异步 action 应 await。

小结

actions 是方法，用 this 访问 state；可同步可异步，封装业务逻辑。

三、综合示例：CTTS-Frontend userStore

src/stores/user.js：

import { defineStore } from 'pinia'

export const useUserStore = defineStore('user', {
  state: () => ({
    token: localStorage.getItem('token') || '',
    userInfo: JSON.parse(localStorage.getItem('userInfo') || 'null')
  }),
  getters: {
    isLogin: (state) => !!state.token,
    username: (state) => state.userInfo?.username || '未登录',
    role: (state) => state.userInfo?.role || 'guest'
  },
  actions: {
    async login(credentials) {
      // 简化：实际调后端接口（第 14 次课）
      const mockData = {
        token: 'fake-token-' + Date.now(),
        userInfo: { id: 1, username: credentials.username, role: 'admin' }
      }
      this.token = mockData.token
      this.userInfo = mockData.userInfo
      localStorage.setItem('token', this.token)
      localStorage.setItem('userInfo', JSON.stringify(this.userInfo))
    },
    logout() {
      this.token = ''
      this.userInfo = null
      localStorage.removeItem('token')
      localStorage.removeItem('userInfo')
    }
  }
})

Login.vue 使用：

<template>
  <form @submit.prevent="onLogin">
    <input v-model="form.username" placeholder="用户名" />
    <input v-model="form.password" type="password" placeholder="密码" />
    <button type="submit">登录</button>
  </form>
</template>
<script setup>
import { reactive } from 'vue'
import { useRouter } from 'vue-router'
import { useUserStore } from '../stores/user'
const form = reactive({ username: '', password: '' })
const router = useRouter()
const userStore = useUserStore()
const onLogin = async () => {
  await userStore.login(form)
  router.push('/projects')
}
</script>

Header 显示用户：

<template>
  <header>
    <span>{{ userStore.username }}</span>
    <button v-if="userStore.isLogin" @click="userStore.logout">退出</button>
  </header>
</template>
<script setup>
import { useUserStore } from '../stores/user'
const userStore = useUserStore()
</script>

运行方式：配置 store，登录后用户信息全局可读，Header 显示用户名，退出清空。
