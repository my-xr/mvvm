二、知识点详解

知识点 K16-1：路由整合与权限守卫

定义

整合全部页面路由，配置 meta 权限与全局守卫，形成完整导航体系。

完整路由表

// src/router/index.js
import { createRouter, createWebHistory } from 'vue-router'
import Layout from '../views/Layout.vue'

const routes = [
  { path: '/login', component: () => import('../views/Login.vue'), meta: { title: '登录' } },
  {
    path: '/',
    component: Layout,
    meta: { requireAuth: true },
    children: [
      { path: '', redirect: '/projects' },
      { path: 'projects', component: () => import('../views/Projects.vue'), meta: { title: '项目列表' } },
      { path: 'projects/:id/tasks', component: () => import('../views/TaskList.vue'), meta: { title: '任务列表' } },
      { path: 'tasks/:id', component: () => import('../views/TaskDetail.vue'), props: true, meta: { title: '任务详情' } },
      { path: 'tasks/:id/submit', component: () => import('../views/SubmitForm.vue'), props: true, meta: { title: '成果提交' } },
      { path: 'reviews', component: () => import('../views/Reviews.vue'), meta: { title: '评审列表', role: 'teacher' } },
      { path: 'reviews/:id', component: () => import('../views/ReviewDetail.vue'), props: true, meta: { title: '评审详情', role: 'teacher' } },
      { path: 'admin/users', component: () => import('../views/Users.vue'), meta: { title: '用户管理', role: 'admin' } },
      { path: 'profile', component: () => import('../views/Profile.vue'), meta: { title: '个人中心' } }
    ]
  },
  { path: '/:pathMatch(.*)*', component: () => import('../views/NotFound.vue') }
]

const router = createRouter({ history: createWebHistory(), routes })

router.beforeEach((to) => {
  document.title = to.meta.title || 'CTTS'
  const userStore = useUserStore()
  if (to.meta.requireAuth && !userStore.isLogin) return '/login'
  if (to.meta.role && userStore.role !== to.meta.role) return '/projects'
})

export default router

小结

整合全部路由 + meta 权限 + beforeEach 守卫 + 404，形成完整导航。

知识点 K16-2：状态管理整合

定义

将 userStore/projectStore/appStore 接入各页面，实现全局状态共享。

整合要点

  • userStore：登录页调 login；Header 读用户名与退出；守卫读 isLogin/role。
  • projectStore：项目列表页调 fetchProjects 缓存数据。
  • appStore：布局组件侧边栏折叠状态。

小结

三 store 接入对应页面，实现登录态、数据缓存、UI 状态全局共享。

知识点 K16-3：接口联调完善

定义

将 Mock 数据替换为真实后端接口，完成前后端联调。

流程

  1. 确认后端接口已就绪（CTTS 后端）。
  2. 移除 api 函数中的 Mock 兜底，改为真实 request.get/post。
  3. 配置 Vite proxy 指向后端地址。
  4. 联调测试各页面数据交互。
  5. 处理字段不一致、错误码等问题。

小结

Mock 替换为真实接口，配置 proxy，联调测试，处理契约问题。

知识点 K16-4：vite build 构建

定义

vite build 把项目构建为生产环境静态文件，输出到 dist 目录。

构建命令

npm run build

构建产物

图示 1：Vite 构建产物 dist 目录
  • dist/
  • index.html # 部署入口 HTML
  • assets/
    • index-xxxx.js # 打包后的 JS，文件名带哈希
    • index-xxxx.css # 打包后的 CSS
    • ... # 图片、字体等其他静态资源

预览构建结果

npm run preview            # 启动预览服务器查看构建产物

构建优化

  • 代码分割：路由懒加载自动分割 chunk。
  • Tree-shaking：移除未用代码。
  • 压缩：JS/CSS 压缩。
  • base 路径：部署到子路径时配置 vite.config.js 的 base。
// vite.config.js
export default defineConfig({
  base: '/ctts/',           // 部署到子路径
  plugins: [vue()]
})

易错点

  • 构建报错：检查语法错误、未导入的组件。
  • 资源路径 404：部署到子路径需配置 base。
  • 环境变量：开发与生产 API 地址不同，用 .env 文件管理。

小结

npm run build 构建到 dist；npm run preview 预览；注意 base 路径与环境变量。

知识点 K16-5：部署与答辩

部署方式

方式一：静态服务器（Nginx）

server {
  listen 80;
  server_name your-domain.com;
  root /path/to/dist;
  index index.html;
  location / {
    try_files $uri $uri/ /index.html;     # history 模式回退
  }
  location /api/ {
    proxy_pass http://backend:8080/;      # 代理后端 API
  }
}

方式二：Vercel/Netlify 等平台

  • 上传 dist 或连接 git 仓库自动部署。
  • 配置 SPA 路由回退（Rewrite to index.html）。

方式三：简易预览

npm run build
npm run preview -- --port 4173

history 模式部署注意

  • 服务器需配置所有路径回退到 index.html，否则刷新 404。
  • Nginx 用 try_files $uri $uri/ /index.html。

答辩要点

  1. 功能演示：展示登录、列表、详情、提交、评审、用户管理等核心流程。
  2. 技术讲解：说明架构（组件化/路由/状态/请求）与技术选型。
  3. 问题应对：回答老师与同学提问。
  4. 总结反思：项目亮点、不足、改进方向。

小结

部署用 Nginx（配置回退）或平台；答辩展示功能、讲解架构、应对提问。
