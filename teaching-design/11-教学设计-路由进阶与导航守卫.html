二、教学目标

知识目标

  1. 掌握全局守卫 beforeEach、afterEach。
  2. 理解路由独享守卫与组件内守卫。
  3. 掌握路由元信息 meta 实现权限控制。
  4. 掌握路由懒加载与代码分割。
  5. 掌握重定向与 404 页面配置。

能力目标

  1. 能用 beforeEach 实现登录权限拦截。
  2. 能用 meta 实现角色路由控制。
  3. 能配置 404 页面与重定向。
  4. 能完成 CTTS-Frontend 登录权限与角色路由控制。

素质目标（课程思政）

  1. 培养安全意识——前端路由守卫是权限的第一道防线。
  2. 建立防御性编程思维——权限校验要前后端结合。

三、主要知识点纲要

编号 知识点 要点
K11-1 全局守卫 beforeEach（前置）/ afterEach（后置）；next 放行/重定向/取消
K11-2 独享与组件内守卫 beforeEnter 路由独享；onBeforeRouteLeave/onBeforeRouteUpdate 组件内
K11-3 路由元信息 meta meta: { requireAuth, role }；守卫中读取 meta 判断权限
K11-4 路由懒加载与代码分割 () => import()；分组；按需加载优化首屏
K11-5 重定向与 404 redirect；{ path: '/:pathMatch(.*)*', component: NotFound }

四、项目任务或案例任务

本次课任务：实现 CTTS-Frontend 登录权限拦截（未登录跳转登录页）与角色路由控制（学生/教师/管理员访问不同页面）。

五、课堂互动设计

互动 1：面试题快问快答——导航守卫

项目 内容
互动问题 "导航守卫有几种？执行顺序是怎样的？"
教师点评要点 全局/独享/组件内三类；顺序：beforeEach → beforeEnter → 组件内 → afterEach

互动 2：前端权限 vs 后端权限

项目 内容
互动问题 "前端守卫能保证安全吗？为什么还要后端校验？"
教师点评要点 前端守卫只是体验优化（挡住无权限页面），真正的安全靠后端校验，前端可被绕过

六、课程思政融入点

项目 内容
融入点 安全意识——路由守卫是权限第一道防线
技术关联 守卫拦截未授权访问，保护用户数据
引导问题 "如果前端不做权限拦截，用户直接输 URL 会怎样？"
预期价值目标 树立安全意识与防御性编程思维

七、课堂练习或随堂测验（5 分钟）

判断题：

  1. beforeEach 是全局前置守卫。（✓）
  2. meta 可存储路由元信息用于权限判断。（✓）
  3. 前端守卫能完全保证安全，无需后端校验。（✗）
  4. 404 页面用 :pathMatch(.*)* 匹配。（✓）

详细题目见 题库.md。
