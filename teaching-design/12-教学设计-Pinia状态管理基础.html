二、教学目标

知识目标

  1. 理解 Pinia 的定位与对比 Vuex 的优势。
  2. 掌握 defineStore 定义 store。
  3. 掌握 state（定义/读取/修改）。
  4. 掌握 getters（计算状态）。
  5. 掌握 actions（同步/异步方法）。

能力目标

  1. 能创建 Pinia store 管理全局状态。
  2. 能在组件中读取与修改 store 状态。
  3. 能创建 CTTS-Frontend 的 userStore（管理 Token/用户信息/登录状态）。

素质目标（课程思政）

  1. 培养数据管理意识——全局状态是前端架构的核心。
  2. 建立"单一数据源"思维——共享状态集中管理避免混乱。

三、主要知识点纲要

编号 知识点 要点
K12-1 Pinia 简介与对比 Vuex Vue3 官方推荐；无 mutations；TS 友好；更简洁
K12-2 defineStore 定义 store 安装；createPinia；defineStore('名字', 配置)
K12-3 state 定义状态；组件读取；修改方式（直接改/$patch）
K12-4 getters 计算状态；类似 computed；依赖 state
K12-5 actions 定义方法；同步/异步；修改 state

四、项目任务或案例任务

本次课任务：创建 CTTS-Frontend 的 userStore，管理 Token、用户信息、登录状态，提供 login/logout action。

五、课堂互动设计

互动 1：小组讨论——哪些数据放 Pinia

项目 内容
互动问题 "哪些数据应该放 Pinia，哪些放组件本地？"
教师点评要点 多组件共享的放 Pinia（用户信息/Token/全局 UI 状态）；组件私有放本地

互动 2：Pinia vs Vuex

项目 内容
互动问题 "Pinia 相比 Vuex 少了什么？为什么更简单？"
教师点评要点 Pinia 去掉了 mutations，异步直接在 actions 写；TS 更友好

六、课程思政融入点

项目 内容
融入点 数据管理意识——全局状态是前端架构核心
技术关联 集中管理共享状态，避免组件间数据混乱
引导问题 "没有状态管理，多个组件共享用户信息会怎样？"
预期价值目标 培养架构意识与单一数据源思维

七、课堂练习或随堂测验（5 分钟）

判断题：

  1. Pinia 是 Vue3 官方推荐的状态管理库。（✓）
  2. Pinia 需要 mutations 修改状态。（✗）
  3. getters 类似 computed。（✓）
  4. actions 可以是异步函数。（✓）

详细题目见 题库.md。

八、课后任务

  1. 通读 教学资料.md，掌握 Pinia store 定义与使用。
  2. 完善 userStore：增加修改密码 action。
  3. 思考：Pinia 与 Vuex 的区别（200 字）。
